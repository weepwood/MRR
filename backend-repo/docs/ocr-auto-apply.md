# 已验收类别自动归类与回退（阶段五）

关联 #342。P1。自动应用默认关闭，部署并不表示识别质量已经验收。

## 独立证据与启用

院内在受控目录准备 JSONL 验收数据，每页包含 groupHash（病案分组的加盐哈希）、
pageHash（页面内容哈希）、expectedType、predictedType、autoEligible、clearPrinted；
清晰印刷页还包含 referenceText 和 recognizedText。输入可能包含患者正文，只能保留在
院内受控目录，不提交 Git、日志、Issue 或 Artifact。输出报告只含聚合数据与输入校验值。

使用 ocr-runtime/evaluate.py，传入独立验收集、调参分组哈希清单、固定规则版本和模型清单哈希。
工具拒绝调参/验收病案交叉及重复页面，计算字符编辑距离 CER、自动错误与各类覆盖数量。
必须至少 2000 页、600 个自动候选且零误分、至少 100 页清晰印刷文字 CER≤5%。
单个拟启用类别还须至少 30 个独立自动候选且零误分。此为本版本保守准入门槛，不是每类
99.5% 精度的统计证明；还需医院业务人员独立复核并持续抽样。证据不足的类别只生成建议。

运维以不可变文件交付报告，配置：

```properties
ocr.runtime.auto-apply-allowed=true
ocr.runtime.validation-report=本机受控报告绝对路径
ocr.runtime.validation-report-sha256=真实报告SHA256
ocr.runtime.auto-types=经复核允许启用的类型编号
```

以上为字段说明，不是可直接使用的生产值。随后开启设置页“已验收类别自动归类总开关”。
历史批次预览展示可启用类别；授权用户勾选本批次自动归类后再次预览，创建请求绑定报告校验值。
前端不能上传验收报告、设置模型路径、声明模型已验收或伪造授权人。
后台在实际变更时重读账号、权限、报告哈希、规则/模型绑定、源哈希、OCR 版本、类型与版本。

## 自动应用与审计

仅原类型仍为 0、明确独占标题、标题置信度≥0.98、整页≥0.90且通过以上门槛才可自动应用。
正式类型、建议确认、自动处理状态与审计原子提交。执行方式记录 BACKGROUND，操作者字段
代表真实授权人，审计同时记录批次、报告校验值、建议与 OCR 版本，不伪装为逐页人工确认。
不符合条件或执行失败则进入人工审核；账号撤权暂停批次；源变化使 OCR 过期。
关闭总开关立即停止后续自动变更；已完成的文字识别和人工审核不因此删除。

## 数据回退

先关闭自动总开关，并暂停/取消批次。回退预览最多 100 条，页面默认 50 条。
仅回退最后一次审计仍为该批次自动应用、当前类型/版本/病案归属均相同且未回退过的页面。
后续人工操作即使确认相同类型也递增版本，因此不会被回退覆盖。
每页短事务恢复为 0 并追加 ROLLBACK_AUTO 审计，引用原审计；重复请求不会重复回退。
请求中断时从返回游标继续，也可以重试同一游标，已处理页面会跳过。

## 验证

2026-10-18：15 项 OCR/分类/进程/资源/质量单元测试、16 项 PostgreSQL 16 集成测试通过。
真实子进程验证 UTF-8、复用、超时及超限；数据库验证自动应用审计、重放、源与类型变化拒绝、
审计失败回滚、撤权停止及回退保护后续人工确认。Python 评测和运行时边界测试通过。
这些是合成数据工程验证，不替代院内 2000 页真实质量验收。
