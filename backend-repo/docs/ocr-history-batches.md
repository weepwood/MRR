# 历史未分类 OCR 批次（阶段四）

关联 #342。P1。此阶段只运行 OCR 与分类建议，自动落库尚未开放。

## 范围与运行条件

管理页“历史影像识别”先预览起止 ID 和最多页数，再创建固定上界的有限批次。
预览最多读取 maxPages+1 条候选，显示本次范围内的上限，不声称全库精确数量。
只选择有效、btype=0、archive_id 存在且编号与主档一致的页面；异常用 ocr-preflight.sql 隔离统计。
每批最多 10000 页，最多 10 个活动/暂停批次；每次最多登记 200 页，队列最多 100 个活动病案任务。
上一游标段的任务完成后才登记下一段，同病案唯一活动约束继续生效。
游标与所有子任务/页面登记在同一 PostgreSQL 事务中提交；失败回滚整个游标段。

默认窗口为 Asia/Shanghai 22:00–06:00。先以关闭 OCR 的状态测量正常调阅 P95，配置：

```properties
ocr.runtime.image-p95-baseline-millis=实际测得的毫秒值
```

这不是可直接粘贴的数值。已有 HTTP timer 增加影像路由 P95；无基线、无测量、
CPU 连续 5 分钟超过 70%、可用内存不足 20% 或 P95 恶化超过 10% 时停止历史领取。
无影像流量导致测量窗口过期时保持等待；不得通过伪造基线绕过。
单病案手动任务不受历史窗口限制，并且优先领取。

## 暂停、取消与权限

暂停在当前页完成后停止领取历史页，不影响手动任务；续跑从持久化检查点恢复。
取消会取消已登记子任务，取消处理不受夜间/资源门槛限制；已成功文字保留。
ocr:batch-run、ocr:run 和 record:read 必须同时具备。创建人或管理员可以管理批次。
批次授权使用真实账号 ID；后台重新检查账号/权限，撤权后暂停或取消后续执行。

## 数据库与回退

新增批次结构及两个未分类候选部分索引；索引独立非事务并发建立。
索引失败时先检查 pg_index.indisvalid 与 Flyway 失败记录，再按运维流程修复后重跑；
不得修改已有 main 迁移。新索引迁移在重试时会重新构建该迁移拥有的索引。
三千万级副本上仍须执行 EXPLAIN (ANALYZE, BUFFERS)、评估磁盘与构建时间。
关闭 OCR，取消或暂停批次后可以回退应用；保留任务、文字与索引，不直接删除数据。

## 本地验证

2026-10-18：相关单元测试和 PostgreSQL 16 的 11 项 OCR/分类/批次集成测试通过。
批次测试覆盖 200 页游标段、201 页总上限、重复调度不重复登记、暂停后无法领取、
取消绕过资源门槛，以及子任务登记失败时游标和任务均回滚。前端类型检查通过。
目标 Windows Server、实际存储和生产规模性能尚待验收，默认不开启历史处理。
