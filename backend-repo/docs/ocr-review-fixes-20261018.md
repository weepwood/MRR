## 问题与修复

| 问题 | 原因及影响 | 修复与回归证据 |
| --- | --- | --- |
| 审核期间 OCR 版本可被替换 | 审核锁住建议与影像，但普通 SELECT 读取 OCR 事实后，另一连接仍能在改类提交前替换事实 | 改用既有 lockFact，锁顺序保持建议→影像→OCR事实。PostgreSQL并发测试修复前失败：另一连接的版本替换提前完成；修复后须等待审核提交。已先提交的新版本仍拒绝旧建议，正式类型和审计不变 |
| 中间PR发布基线过期 | 新迁移已随阶段引入，maximumCompatibleMigration修正却只在最后一个PR；#344实际校验退出1 | #344/#345/#346/#347分别固定到10000/20000/30100/40000结尾的阶段迁移，附完整应用回退说明；四个阶段逐个检出并执行release_baseline.py validate，全部通过。仅追加提交并合入上游，不强制推送 |
| 关闭OCR保留空闲模型进程 | 调度器只停止领取，成功返回后等待stdin的常驻Python没有在关闭路径回收 | 关闭后的下一次调度检查（默认1秒）调用引擎reset，杀死已登记进程及子进程、清空登记，协议执行器保留以支持重新启用。真实进程测试修复前等待退出超时，修复后进程退出，重新开启启动新PID |
| 关闭时迟到的启动与进程清理竞争 | 如果只遍历并清空进程表，已通过检查但未登记的启动可能逃过回收；取消检查本身可能等待数据库 | 只对进程登记/回收持有监视器；取消查询放在监视器外，使用代次号阻止关闭前的迟到登记。回归测试暂停取消查询，reset须在1秒内完成，随后迟到调用返回CANCELLED |
| 读源期间关闭仍可能自动改类 | 自动应用只在runOne入口检查ocrEnabled，读取文件结束后的事务未复核 | 读源取消条件及短事务入口再次检查OCR开关。PostgreSQL测试修复前正式类型从0变为3；修复后保持0且无改类审计，开启后仍可继续处理 |

文件读取和识别仍在数据库事务之外。加锁不改变权限、正式类型阈值或识别规则；没有新增或修改任何数据库迁移。
关闭行为是由调度轮询观察，不承诺设置HTTP请求返回时所有操作都已经同步退出；进程清理不等待单页识别超时。

独立审查通过PostgreSQL16合成数据库确定复现一个P2阻塞：旧worker在next后暂停，租约过期，新worker完成任务并release；

新增回归在旧代码实际失败（期望NO_MATCH，实际PROCESSING）。修复在processing语句中用CTE锁定父任务行，原子检查
token、未过期租约、RUNNING、未取消及子项未终态；返回0时服务立即退出，不读取源、不发布结果。
父任务行锁同时防止读取旧MVCC租约后再更新子项的检查/写入窗口。修复回填#344并依次普通merge至#348，无新增迁移。
