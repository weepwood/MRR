# ADR-0001：离线 OCR 与受控未分类影像自动归类

- 状态：Accepted（2026-10-18；用户确认方案并授权独立审查后合并）
- 日期：2026-10-18
- 关联 Issue：#91、#146、#142、#147；新增变更提案见 docs/engineering/ocr-change-proposal.md
- 决策依据：用户已确认的 OCR 实施方案；独立代理规格与代码审查通过，详见 #342。生产启用仍受院内质量与目标环境验收门槛约束。

## 背景与决策

OCR 基础表已存在，执行链路尚未实现。采用 Spring Boot 编排 PostgreSQL 持久化任务，
通过受限标准输入输出调用同机常驻 RapidOCR / ONNX Runtime CPU 子进程。
引擎无数据库权限、不开放网络服务；模型与运行时离线交付并固定版本及哈希。

历史批次只是单病案任务的有限编排，不建立第二套识别队列。OCR 事实、版本化规则建议
和 mr_scan.btype 分离。明确授权的自动应用作为独立类型变更事务，记录真实授权人与后台
执行方式；它不伪装为逐页人工审核。已有分类不得自动覆盖。

## 必须保持的不变量与边界

- 不引入 Docker 生产依赖、Redis、Kafka、微服务或云 OCR。
- 输入仅为后端统一存储接口读取的受控文件；前端不提供路径/命令/凭据。
- 自动应用仅限 btype=0 且版本和源指纹未变化；重新检查授权人的有效账号及权限。
- 同病案一个活动任务；游标、租约、重试均持久化，有取消和资源上限。
- 原文不被词库纠错覆盖；正式改类及审计原子提交；回退保留审计并尊重后续人工修改。
- 未完成独立质量验证的类别不可自动应用；文字识别失败不影响影像调阅。
- 不处理全文搜索、结构化表格、手写专项、新扫描流水线和历史已分类页。

## 替代方案

云 OCR 不符合本次离线隐私边界；独立 HTTP 推理服务增加运维组件；JVM 内直接推理
使本地推理崩溃和资源失控影响业务进程；逐页新建进程重复加载模型降低历史吞吐。
仅人工确认更保守，但不满足用户明确要求的高置信度未分类自动归类。

## 影响与迁移

扩展既有表，新增结果历史、批次、持久化授权与类型版本；不修改历史 Flyway。
大表 DDL 设置锁等待上限，候选索引独立并发创建。统一既有人工改类与通用更新入口的审计。
离线 Python、模型及 Windows VC++ 运行库需要版本化交付；主机平台和 ISA 必须实测。
前端使用已有 Axios、权限、档案袋与设计 Token，支持 Chrome 86；运维脚本支持 PS 5.1。

## 回滚与前向修复

OCR/自动应用默认关闭，暂停领取后可回退应用和模型版本。保留事实与审计表。
按批次回退只能撤销仍为最后一次自动变更的记录，追加回退审计；后续人工变更跳过。
禁止删除审计或直接还原整个 mr_scan；数据库问题新增迁移修复。

## 验证

先失败测试，再实现权限、进程上限、状态机、事务、幂等和并发保护。
PostgreSQL 16 集成测试及 EXPLAIN；Windows/存储/断网/Chrome 86 实测。
至少 2000 页院内受控样本，独立自动候选至少 600 个零误分，目标准确率 ≥99.5%。
真实证据未具备时只上线关闭状态，禁止宣称满足识别质量或生产性能。
