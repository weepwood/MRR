# ADR-0002：可恢复的隐私日志与请求诊断

状态：Accepted（用户已确认实施方案）。关联 #349、#137、#111。

## 背景

MRR 使用 Windows 单机和 PostgreSQL；现有内存错误队列无法恢复数据库故障期间的事件，非传播 logger 可能绕开 root 采集器。将原始格式化日志直接入库会复制患者、凭据与存储信息。

## 决策

统一脱敏 JSON 文件作为运行日志事实源，单实例采集器使用文件标识和字节偏移幂等补录。数据库保存按月分区的运行日志及采集断点，错误中心是同一事件流的聚合投影；不建立第二套认证、审计或请求层。

文件编码和兼容错误采集共享物理事件UUID；错误聚合使用独立的持久化投影收据，与聚合更新在同一SQL中原子提交。日志采集关闭期间已聚合的事件重新补录仅保存明细，不能重复计数；收据不随开关切换清除。旧文件没有UUID时沿用源标识和偏移生成稳定身份；更早版本已经写入错误中心但没有收据的历史日志无法可靠反推同一事件，历史补录仅建明细、不重新聚合。

日志 message 使用模板，参数不直接序列化；异常保留类型与代码栈，剔除异常正文。业务审计按结构解析，未知参数默认隐藏；编号仅保留掩码和使用独立 `MRR_AUDIT_HMAC_KEY` 的检索摘要，密钥缺失时只隐藏，不回退普通哈希或复用 JWT/外部票据密钥。

管理员详情需要运维与病案读取权限；业务人员仅看到安全原因和 Request ID。所有敏感响应 no-store。诊断不得成为任意 SQL、文件路径或 URL 探测入口。

采集实际启用级别产生的日志，不全局开启 DEBUG。长期数据库明细不自动删除；本地未确认日志受独立配额约束。数据库故障不阻塞医疗业务；缓冲耗尽必须暴露缺口、已知丢失数及不可计数区间。

## 替代方案

同步写库扩大数据库故障影响；纯内存队列不耐重启；ELK/外部平台改变部署边界。均不采用。

## 影响

增加本地磁盘、数据库、备份和维护容量；运行日志默认不展示参数原文，会降低自由文本细节，但以可信 Request ID、结构化原因和授权业务页面补足。

## 迁移和回滚

新增表与迁移，不改变历史迁移。运行采集开关可关闭，已有日志保留；老错误 API 保持兼容。历史文件通过固定目录清单受控补录，解析失败不保存原文。回滚不得恢复敏感原文输出。

## 验证

验证真实 Logback 配置、全部已产生级别、日志轮转、断点、重复读取、故障恢复与磁盘满；PostgreSQL 16 验证幂等与投影事务；前端验证权限、游标和文本渲染。生产等量副本对比 P95，新增采集开销目标不超过 10%。医院容量与性能须现场复核。
