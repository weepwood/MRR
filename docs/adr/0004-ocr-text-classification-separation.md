# ADR-0004：OCR 文本、分类建议与正式类型分离（第一阶段，默认关闭）

- 状态：Accepted（第一阶段历史决策；受控自动归类由 ADR-0001 扩展）
- 日期：2026-10-09（补录；实现随 v0.8.0 合入 `main`，最高兼容迁移 `20260724220200`）
- 决策者：MRR Team
- 关联 Issue：#91、#342
- 关联 PR：#236；后续扩展见 #343–#348
- 替代 ADR：无

## 背景

影像类型（btype 0-14）是病案管理的关键元数据，当前由人工设定。引入 OCR 与智能分类可辅助录入，但若自动分类结果直接覆盖人工确认的正式类型，会破坏数据可信度与审计链。同时 OCR 调用本地可执行程序存在命令注入与越权风险（AGENTS.md：不接受前端传入任意本地可执行程序路径或命令）。

约束：

- OCR 文本、模型分类"建议"、人工确认的"正式类型"三者必须分离；
- 已分类影像不得被自动分类静默覆盖；
- 正式类型变更必须有真实操作者身份、权限与不可伪造审计；
- OCR 仅限服务端白名单配置，禁止前端指定本地程序；
- 第一阶段不允许改变既有业务语义，必须可整体回滚。

## 决策

OCR 第一阶段仅新增**独立表、索引、默认设置与管理员权限**，不修改当时的业务字段：

- `ocr_text`：保存 OCR 原始文本事实；
- `ocr_classification_jobs`：保存分类任务与建议结果（含置信度）；
- `ocr_settings`（写入 `mr_system_settings`）：`ocrEnabled=false`（默认关闭）、`ocrProfile`（服务端白名单）、`ocrLanguages`、`ocrMaxConcurrency`、`ocrPageTimeoutSeconds`、`ocrMaxOutputBytes`、`ocrAutoProcessNewScans=false`、`ocrLowConfidenceThreshold`、`classificationBatchReviewThreshold=0.92`；
- 权限：`ocr:read`/`ocr:run`/`ocr:config`、`classification:read`/`review`/`batch-review`/`override`（初始仅 ADMIN）。

核心规则：

- OCR 文本与分类"建议"与"正式类型"物理分离，互不直接写回 `btype`；
- 第一阶段的分类仅产生建议，人工在审核界面确认后才可能变更正式类型；2026-10-18 接受的 ADR-0001 后续增加了受控自动应用，仅限仍未分类的影像；
- 批量确认设阈值（≥0.92）、范围、失败恢复与抽样复核；
- OCR 执行受白名单、并发、超时、输出上限约束，结果异步、有状态、可取消/恢复/配额/过期/审计。

## 必须保持的不变量

- 第一阶段的正式类型变更由人工确认；后续受控自动应用须遵守 ADR-0001 的真实授权人、权限复核、事务审计与回退边界；
- OCR 产物不得静默覆盖既有正式类型；
- 本地 OCR 程序路径只来自服务端白名单，前端不可指定；
- OCR 功能默认关闭，开启不改变既有查询/导出语义。

## 方案边界

### 包含

- OCR 文本与分类任务的采集、存储、查询；
- 分类建议的展示与人工审核确认；
- 白名单、并发、超时、输出上限等执行约束；
- 管理员配置与权限。

### 不包含

- 自动改写正式类型的无人值守流水线（第一阶段禁止）；
- DICOM 窗宽窗位/医学测量/诊断结论（MRR 明确不做）；
- 模型训练或自研模型，仅消费外部 OCR 配置。

## 替代方案

### 方案 A：OCR 直接写回 btype

- 优点：录入最省事。
- 缺点：破坏正式类型权威性与审计；错误分类不可逆污染数据。
- 未采用原因：违反"已分类影像不得被自动分类静默覆盖"。

### 方案 B：前端直连 OCR 服务

- 优点：后端改动小。
- 缺点：绕过服务端白名单与审计，存在命令注入与凭据外泄。
- 未采用原因：违反本地程序白名单与权限边界。

## 影响

### 正面影响

- 在不污染正式数据的前提下获得 OCR 辅助能力；
- 默认关闭，零侵入，可灰度开启。

### 负面影响与技术债

- OCR 文本/建议表会随扫描量增长，需容量规划；
- 分类建议与正式类型的对账逻辑待第二阶段明确；
- 当前仅 ADMIN 有权限，普通医生/护士无法使用，需后续角色设计。

### 安全、隐私与审计

- OCR 输出可能含身份证号等敏感文本，存储与展示需脱敏；
- 正式类型变更路径复用既有审计，OCR 仅贡献"建议"。

### 数据库、性能与容量

- 新增 3 套结构（ocr_text、ocr_classification_jobs、ocr_settings）；
- `mr_scan` 三千万级，OCR 任务不得无界扫描，需基于现有索引分批。

### Chrome 86、Windows 与部署兼容性

- OCR 进程在 Windows Server 后端运行，前端仅消费结果，不影响兼容。

## 迁移方案

- 数据库：`V20260724220000`（ocr_text）、`V20260724220100`（ocr_classification_jobs）、`V20260724220200`（ocr_settings + ADMIN 权限）；
- 配置：默认 `ocrEnabled=false`，运维按需配置白名单后开启；
- 代码：OCR 执行受 `ocrProfile` 白名单约束；
- 文档：内部文档补充 OCR 与分类说明、运维指南补充白名单配置。

## 回滚与前向修复

- 应用回滚到上一版本可忽略新增结构（release-baseline 已确认 `backwardCompatibleWithPreviousApplication=true`）；
- 已发布迁移 `V2026072422xxxx` **不得回写**；
- 回滚前仍应备份数据库、外部配置与完整发布目录；
- 若需彻底下线 OCR，以后向迁移置 `ocrEnabled=false` 并停止任务调度，不删表。

## 验证

- 单元测试：`SystemSettingServiceOcrValidationTest`、OCR 配置校验；
- PostgreSQL 集成测试：OCR 任务状态机、白名单拒绝非白名单配置；
- E2E 或手工流程：开启 OCR→扫描→产生文本与建议→人工审核确认→正式类型变更走审计；
- 性能与容量：高并发下 `ocrMaxConcurrency=1` 的吞吐与超时表现；
- 生产或灰度验证：单院区灰度，观察 OCR 输出敏感信息脱敏。

## 后续决策

ADR-0001 在 2026-10-18 扩展了本阶段的人工审核边界：满足独立质量验收的类别，可在真实用户明确授权后，对仍为 `btype=0` 且版本及源指纹未变化的影像自动应用正式类型。自动操作记录授权人与执行方式，不伪装为逐页人工确认；OCR 与自动应用仍默认关闭。生产启用条件由 #342 跟踪。
