# ADR-0007：历史 OCR 按有效上架号逐案处理与受限页序建议

- 状态：Accepted（2026-10-25 用户确认方案并授权实施；合并仍须独立审查）
- 关联：#417、#342；扩展 ADR-0001，不改变其自动应用准入条件

## 背景与决策

先按扫描ID分段再按主档分组会切断病案，单页规则无法表达续页和正反面线索。
使用非空上架号，否则病案号，作为有效分组编号；编号保留前导零，仅去首尾空格。
执行仍绑定已核验的 archive_id。同一有效编号对应多个主档时隔离，不猜测合并。
不回写 sjh，不改变原文件路径。

历史批次复用现有 PostgreSQL 队列和创建事务锁，逐份登记完整未分类页面清单。
冻结页面的 pages/id 顺序；同一份OCR与上下文分析收尾、自动变更完成或降级审核后再登记下一份。
暂停的当前病案保留历史处理位置，手动任务仍优先。旧批次保留原调度模式。

OCR后的第二遍每次只分析一页及最多两张前页，使用独立明确标题作为参考。
续页必须自身含续页标识并与参考页尺寸兼容；新标题、缺页、重复页码、失败和冲突正式分类阻断。
最多延续两页，不将推断结果作为新的独立标题。正反面还需显式背面/反面标识，不用奇偶配对。
上下文结果始终是人工建议；参考页源哈希、OCR/类型版本和页序保存在证据中，审核时复查。
关系的确认/解除独立记录真实审核人和追加审计，不合并原始图片。解除待审核关系同时拒绝对应建议。

## 不变量与替代方案

OCR事实、建议与正式类型分离。正式改类仍经过 ImageTypeService 的权限、版本和审计短事务。
不采用整案OCR文本一次性载入、无限邻页传播、固定奇偶配对、第二套队列或云服务。
仅按病案号分组不符合上架号唯一规则；直接合并冲突主档会混案，均不采用。

## 影响、迁移与回滚

两个新前向迁移扩展现有任务/建议元数据，新增关系审计和主档有效编号索引。
不回填大影像表；主档表达式索引非事务并发创建，设置3秒锁等待上限，需现场评估磁盘与构建时间。
新库和已有库均走正常Flyway；并发索引中断检查 pg_index/Flyway记录后重试，仅重建本迁移拥有的索引。
接口新增字段和批次 cases 读取，旧 jobs 接口保留；items 的 after 仍传上次最后scanId，服务端按固定页序定位。

不改变现有发布基线的整体回退禁令。先关闭OCR/自动应用，暂停或取消批次，采用本功能提交的安全
前向撤销；保留新增结构、OCR与审计。正式类型只按现有批次回退，不能覆盖后续人工改类。

失败测试先证明整案/页序/配额/参考页竞争问题；PostgreSQL16验证整案登记、全局串行、租约、
退避、游标与建议原子提交、参考源和版本变化、关系审计。前端验证预览、页码、对照和关系审核，
执行类型、构建、Chrome86产物检查及治理。真实质量、Windows Server/存储/Chrome86与大表计划仍需院内验收。
