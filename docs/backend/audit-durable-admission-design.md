# 医疗审计候选：准入、密钥与生命周期设计（第九批）
状态：P1研究设计，未启用正式部署；当前候选仍在afterCompletion，不得描述为响应前零丢失。
## 响应前准入
现有access_log每个request_id最多一条普通审计记录，内容依赖真实HTTP终态；在Servlet提交响应前简单调用原afterCompletion会丢失真实状态，也无法覆盖异步流媒体、外部副作用及异常回滚。建议明确事件语义后再实现两阶段协议：
1. 在认证、授权和请求脱敏之后、医疗内容读取/副作用之前，持久化不可变INTENT（稳定事件ID、关联request_id、权限主体、动作及受保护资源范围），等待同步确认。容量不足、文件系统错误、密钥不可用时拒绝新受保护操作（503），不执行其业务副作用；已有拒绝审计走独立受控容量，不能递归阻塞。不得将所有正常请求一律当医疗读取。
2. 业务执行保持原事务；普通JSON响应结束/流媒体断开/异步结果由独立OUTCOME事件反映真实状态。允许未完成INTENT存在，不能将其伪造为成功，也不在结果不明时重执行医疗副作用。
3. 事件ID与请求ID不同，不应以修改旧唯一约束或历史迁移解决；需要独立前向数据模型、真实审查和兼容期读取方案。既有访问日志及外部调阅专用日志不能被重复计为同一业务事件。
4. 容量必须预留INTENT与OUTCOME预算，避免已准入操作无法收尾；测量流量、密文大小和实际故障恢复时间，容量门禁包括逻辑字节、记录数、文件系统可用空间和I/O时限。现有128等待条数与10k/64MiB是实验参数，不是现场准入SLA；I/O阻塞不允许伪造确认。针对读取与不可逆写操作分别证明先审计后副作用，验收以真实HTTP首字节、断开、超容量及子JVM故障为准。
## 密钥和Windows
- 独立随机32字节密钥；不复用JWT/HMAC、明文数据库配置、日志、Git或诊断包。当前v1/v2格式记录版本与文件名AAD，未提供key-id或在线轮换；错密钥/篡改保留密文并阻止启动，非空队列不得直接换钥。最小可用流程是停准入、保留旧密钥、排空逐ID确认、受控备份、换钥后重启，恢复演练和审计钥匙使用。后续新格式以非秘密key-id绑定AAD，用新钥写、旧钥读，旧段确认并过保留期才退役旧钥；拒绝未知key-id，禁止静默降级。
- 正式环境Windows Server/NTFS、WinSW服务账户：必须验证服务账户专用目录DACL、禁止继承过宽ACL、拒绝重解析点/不可信路径、最小管理员访问及备份恢复；当前POSIX判定严格拒绝Windows，不绕开此门禁。验证NTFS原子重命名和持久化屏障的真实语义、断电与磁盘写缓存、服务重启、更新包装器停机顺序。Windows DPAPI/受保护凭据存储仅为研究候选，未验证实际可用性，不新增依赖。
- 密文是医疗敏感数据；保留期、备份、密钥托管、访问审计、事件响应、删除政策均需医疗数据负责人核准。仅在独立实验生成合成记录。
## 段检查点、过期重放与专用审计
不可变小分组段由文件force/原子发布/目录force保证发布顺序；数据库提交后才删除整段。当前文件集合本身就是待处理索引，重启重新验证，不存在外部易失检查点。未实现长寿命追加WAL、活动段截断、独立检查点或段压缩；未来必须证明检查点落盘先于回收，验证短写、撕裂尾、损坏中段、重复回放，禁止自动截断已确认记录。
- 旧审计保留期清理或分区退役后，仅依赖access_log现存记录不能判定旧事件是否曾落库。需要保留符合隐私要求的最小不可逆幂等凭证及其寿命，或按过期策略进入隔离审查（不能自动丢弃或重建已退休数据）。协作事务锁不等于全局唯一约束；旧写者、手工SQL、混合部署必须明确升级门禁。
- 集合核对发现内容冲突/损坏时目前拒绝整批；需要独立持久隔离清单、可审计人工恢复和不饿死正常段的调度，不能删除未确认密文以取得零积压指标。
- 外部专用审计记录与普通access_log语义不同，签发、交换、读取、撤销、下载都有独立主体和资源范围。统一前置准入及持久化时要保留该独立账本和原事务边界；不能把普通HTTP审计替代专用业务审计。本批未改动专用表写入。
## 验收与回滚
不得以短时性能代替现场容量、小时级、断电与跨实例验证。候选默认关闭；旧格式可由新程序读取，旧程序不能读取v2分组段，降级前停止新增、保留密钥、确认所有v2密文落库并排空，禁止自动删段。未解决的容量/物理I/O/冲突/密钥/Windows/过期/专用审计均为正式采用阻塞。
