# 最终安全契约专项（P1，本地变更提案）

基线 948b36d73612cc52aa7a9427dca658cb41ba72e7（PR850），负责人已授权本地实施。使用独立 worktree；未创建远端 Issue/PR，按高风险提案模板登记，推送/合并/发布另行授权。

## 问题、目标与非目标

- 退出只撤销当前 Token；普通读取在准入检查，不追溯撤销已发送字节。敏感写在事务安全边界复核当前权限。既有管理事务角色锁→操作者行锁→新会话读取不可降低。
- 用户导出任务不依赖原 Token 生存期。开始、写入有界检查点、成果提交检查当前稳定所有者 ID、active、非强制改密及格式权限（包含 record:read 继承）。缺失历史 owner 不以用户名替代；失败关闭。既有所有权、取消、配额、摘要及下载准入保持。撤权后终止后续工作、不得成功发布；已完成文件下载按当前请求授权。迁移任务是独立运维授权，不套用用户注销。
- 关键事务审计：评估现有 access_log、外部持久账本和实验 medical_audit_event；仅对已明确必须原子记录的事件考虑最小事务写入，不开启冻结 spool/admission，不降低脱敏。只读/文件审计的故障策略及保留容量需单独证据，不声称全链路已保证。
- 部署继续 Windows 单机、单后端实例，恢复必须确认旧进程停止；OSS迁移恢复默认关闭，仅批准独占维护。不建设跨主机接管或消息平台。

## 首批实施计划

实际 ArchiveExportJobService.runJob 只检查取消，未读取当前所有者；用真实 PG 合成角色/账号及提交后的撤权复现开始/写入/终态边界。复用 AuthUserMapper.findSessionById、AuthSession 权限解析；最终发布在短事务内按现有角色锁→账号行锁→授权→成功 CAS 顺序执行，避免持锁执行文件 I/O。独立授权组件只负责这一业务边界，不改表、接口或配置。失败状态沿用既有处理，保留持久失败后的文件清理及确认未知后的保守保留。数据库故障不得发布成功。验证旧取消、恢复、摘要、配额、真实HTTP等相关回归。独立代码提交可 revert（开发集成）；安全回退遵循既有发布基线，不直接退回旧生产应用。

待验证：单 Token 在途敏感写、OCR/其他用户任务、事务审计故障策略及实际部署恢复；不因首批通过关闭上述门禁。

## 首批实际验收：异步导出执行授权

- RED：真实PG16、合成角色与用户、独立提交撤权；11例9失败2通过，9个未授权任务错误达到SUCCESS。覆盖ZIP/PDF开始、写入中、发布前撤权，以及历史缺owner、停用、强制改密。正常继承record:manage两个正例通过。
- GREEN：53Java +45PG，98项零失败/错误/跳过，19.701s；追加13PG（含原11、真实角色锁阻塞后撤权、模拟授权DB异常）全通过，9.247s。追加确认写入检查点后未执行第二次写入，真实pg_blocking_pids证明发布锁等待。两个正常授权用例成功；拒绝场景无成功终态、无新成果文件、outputBytes=0。旧取消/IO专项测试只显式模拟新增授权组件，未削弱其原断言；新PG场景使用真实Mapper/事务。RED与GREEN因构造器接线及新增断言不同，非同一测试文件摘要，原11个场景和终态断言保留。
- 实现：使用AuthUserMapper.findSessionById（不读取密码哈希）、现有AuthSession权限继承、既有1s取消轮询检查点、短TransactionTemplate（10s超时）锁ADMIN角色→账号行→授权→markSuccess CAS。普通用户注销不取消任务；现有下载请求仍按实时HTTP准入及所有者/格式授权。撤权失败沿用FAILED及文件清理，DB确认未知时仍保守保留。没有在文件I/O期间持有授权锁；检查点不保证中止阻塞的原生I/O、恢复前已撤权又恢复的账号也不承诺永远取消历史任务。
- 证据：mrr-export-owner-red-20261129.0kQPOb、mrr-export-owner-green-20261129.79iuV9、mrr-export-owner-fence-20261129.IyUG22；最终13份源码摘要全部一致，隔离数据库正常停止。真实HTTP回归覆盖既有下载与权限，不是新Worker场景的真实ZIP/PDF生成或全生产部署验收。

## 其他三项的源码评估及边界

- Token：LoginInterceptor已在Bearer/影像Cookie准入使用observeSession一次数据库查询，失败关闭；UserController.logout只撤销当前jti，改密/停用递增凭据版本。管理事务已有角色锁与账号行锁及当前权限/版本复核，但AuthContext未携带可信Token摘要，因此不能保证已准入敏感写观察单Token在途撤销；下一批优先实际复现该路径，不改变普通读准入契约。
- 审计：access_log是HTTP完成后异步日志，存在容量及故障丢失，保留告警；mr_external_archive_access_log独立外部账本，strict-intent候选仍关闭；mr_image_type_audit已有分类业务审计；medical_audit_event专用于冻结INTENT/OUTCOME实验账本，约束不适用账号变更成功事件。AuthServiceImpl十类账号成功及角色成功仍只afterCommit写SECURITY_AUDIT，日志丢失不能保证事务级持久性。后续应优先低频权限/账号写入的事务内最小事件记录、失败整事务回滚；不把HTTP结果冒充事务结果、不直接改动既有审计历史表或恢复复杂引擎。影像读取的审计故障/容量与外部调阅终态仍须专门核验。
- 单实例：架构与独占维护文档已明确Windows单机及app.migration.recover-on-startup=false；导出启动恢复会resetToPending处理中任务，必须确保前一实例已停止。此次确认约束，不新增运行时分布式锁/自动接管。现场仍须证明没有并行服务以及存储写入已停，不能仅依据数据库锁推断。后续补齐部署手册与恢复门禁。
