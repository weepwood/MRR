# 后端治理第五批（2026-11-26）

基线 2cf45560，启动时工作树干净。P1 认证/医疗隐私/审计/事务，P2 执行预算与性能。仅本地研发；复用第四批隔离 PG16 与实际应用脚本。未触碰正式数据库、历史 Flyway、依赖或远端。以下是风险导向阶段证据，不是正式 P1 审查或小时级验收。

## 已证实缺陷与修复

- LoginInterceptor 原 HandlerInterceptor 在 Spring MVC 异步切换时不执行 afterCompletion，Servlet 线程可能保留 AuthContext。改用 AsyncHandlerInterceptor，在异步交接与完成时清理 ThreadLocal；每次认证开始清理旧线程状态，不取消异步重新认证，不删除 request 上可信身份。
- LogInterceptor 原异步交接未清理 MDC，异步重新分派会重置 requestId/startTime，且没有请求身份时回退到线程身份，可能把匿名请求归属错误。保留原请求标识/开始时间，异步交接清理 MDC，审计仅使用请求绑定身份/外部调阅身份，finally 清理；不减少审计。四个新用例与下项一起 RED 4/4，再 GREEN。
- DeploymentReadinessService 原返回底层异常文本（可能包含连接或医疗字段），现在只公开异常类型及既有检查状态，底层信息不进响应。无权限扩大。
- 旧同步质量入口服务层没有在准入前检查维护/只读，空规则甚至可以直接进入成功。RED 1/1，增加准入检查、样本写入前和终态前再次检查。准入恢复 SQL 共用运行预算；持久截止时间以小数秒计算，减少原先向上取整延长；保留数据库终态条件、唯一活动槽及原有撤权。
- 清理/指标查询共享剩余预算且单 SQL 控制最多3秒；指标成功时间取持久化 completed_at，不以查询刷新时刻冒充成功时刻。成功后的清理/指标失败仍不能改写成功状态。
- 边界：JDBC/Hikari 获取连接仍可等待其独立 connectionTimeout；超期连接返回后拒绝写入不等于调用方必在截止时刻返回。SQL timeout 秒级、数据库锁及驱动/网络、终态修复和响应读取仍不是严格墙钟硬截止。未增加后台执行器/连接池或修改生产池大小。

## 故障与事务

- 真实子 JVM 启动生产 DataQualityServiceImpl（测试限定两条规则），第一条持久化后第二条执行慢 SQL，竞争 JVM 不能领取，强制终止实际子进程；不手工篡改状态/截止时间。数据库真实截止时间到达后另一新 JVM 恢复 FAILED/RUN_DEADLINE_EXPIRED，保留一条规则；下一批由新 JVM 成功执行两条规则。不是完整 Spring Boot 整机崩溃或多节点网络分区。
- 实测运行中取消在约2秒慢规则结束后进入 CANCELLED，不能误称主动打断数据库查询。
- 工单真实 Spring 事务代理与 PG 独立连接：锁争用拒绝、审计失败回滚、同一工单双线程并发 apply 仅一成功、唯一 APPLIED 事件及最终 VERIFIED。复验 Manifest、工单、OCR、导出恢复、迁移等既有状态用例。不等同于全部业务锁顺序、主动死锁注入、重复请求矩阵或外部存储故障。
- 连接池耗尽测试使用独立单连接池，任务预算1秒；持有连接1.5秒后归还，验证超期准入拒绝、零新任务、连接归零；说明硬墙钟预算未达成。
