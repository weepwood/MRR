# 第九批 P1 本地变更提案
基线05ce99b8。首要目标解决第八批候选的同步与SQL成本，默认内存模式不变。先研究不可变加密分组段（不是长寿命可变WAL）：每段最多16条、独立AEAD、文件force、原子发布、目录force后才确认各提交者；完整段落库后批量删除并同步目录，兼容读取v1单条文件。限制等待队列，不承诺物理I/O硬截止。严禁部分段确认。故障保留密文与旧密钥；若损坏/身份冲突不删除。批量SQL使用同一事务、稳定锁顺序、独立新快照、集合读取完整字段、精确等价验证、批量插入；旧协议混用可能死锁回滚，不承诺非协作写者唯一性。P1验证：v1/v2互读边界、容量、强杀、错误密钥、真实PG确认丢失与分区退役竞争，短时对照含原候选及默认；不把短时当长时。Windows ACL、响应前准入、密钥在线轮换、专用审计需单独设计，不启用生产。回滚先排空所有v2段、确认DB，再恢复v1旧代码；不可删除待确认密文或丢密钥。实际业务权限和事务修复仅以RED证据为依据，不修改历史Flyway，不触碰生产，不推送。
