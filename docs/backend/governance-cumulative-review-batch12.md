## 本轮确认问题
1. 医疗admit持有服务锁时读取spool同步getter，容量与慢磁盘屏障耦合；密文解密持有同一发布锁。原子快照和不可变段锁外读取作为独立开关；不缓存明文，不降低force或跳过AEAD。
2. OUTCOME写入异常后只有进程内尝试标记，没有可恢复原始观察；本轮保存精确事件并在同进程恢复时核对/重试。INTENT不确定仍锁止；进程终止前未持久化的OUTCOME无法恢复。
3. 严格签发和兑换的SUCCESS此前由Controller事务提交后尽力记录，现迁至原业务事务；失败回滚。外部流式终态仍不能声称可靠。
4. 第二服务启动全局interrupt/release会影响其他活动任务。默认禁止全局自动恢复；只在管理员核实所有其他迁移工作者停止、明确单实例维护窗口时启用旧恢复开关。此举以牺牲无人值守重启自动恢复换取安全，不能代替失联租约和自动接管。关闭开关后异常遗留任务需人工核对，禁止直接重置来源未知的领取。
5. 条件创建候选此前只信任source-md5元数据；开启条件创建时匹配元数据仍需下载校验内容。实际本地协议测试同时请求一个Key，只允许一写入成功，另一412；不代表医院OSS实施条件语义或跨端不可变性。
## 后续收口
优先修复与验证终态及跨实例工作者安全，不增加新外部医疗缓冲架构，直至独立隐私审查。保持审计目录独立所有权，不采用仅凭时间戳的领取强制回收；租约/围栏必须覆盖数据库和外部对象副作用。孤儿只读核对：在获授权的存储清单（分页、限制条数、不打印对象原始路径）与独立数据库快照间按准确对象键核查所有有效引用、历史引用、活动claim及失败/提交未知证据；采集大小/校验摘要与代次；不把无引用直接视为可删除，保留保护期与人工复核。当前未连接正式OSS、未执行现场盘点、未自动删除。正式门禁：独立审查、实际平台/存储、故障和新候选长时均保留，默认审计不得切换。
