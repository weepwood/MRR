## 2. 产品使用场景与首轮边界

MRR 是院内病案与扫描影像管理系统，核心使用者包括病案调阅人员、数据管理人员、管理员、运维审计人员和外部系统调用方。业务角色不等于新增固定数据库角色；实际授权以既有 RBAC、Controller 和接口测试为准。

首轮围绕历史病案调阅：认证 → 提交查询条件 → 后端确认关联 → 核对病案与影像 → 分类/选页查看 → 按授权打印或限额导出 → 安全重试与审计。以下是设计约束和验收方向，具体实现仍须沿调用链核对：

| 流程 | 必须表达的结果 | 不可越过的边界 |
| --- | --- | --- |
| 身份与进入页面 | 有效会话、拒绝或重新登录 | 前端显示按钮不能替代后端权限 |
| 病案定位 | 唯一结果、缺少条件、歧义、无结果或失败 | 原始编号不自动补零，不猜测关联，不返回第一条掩盖冲突 |
| 影像调阅 | 当前病案、分类、页数和来源失败 | 后端受控读取，不暴露生产凭据、内部路径，不无界加载原图 |
| 打印与 ZIP/PDF | 选页范围、任务状态、限制和可恢复失败 | 生成成功与下载成功分开；不静默截页，不绕过预算回退 |
| 数据治理 | 只读证据、预览和异常范围 | 关系完整性不等于真实文件完整性，预览不等于修复已执行 |
| 运维与交付 | 实际版本、制品、错误关联和恢复结果 | 启动成功不等于恢复成功；日志与证据必须脱敏 |

首轮不要求日常扫描接入、完整生命周期、OCR 自动应用、HIS/EMR 正式联调或完整多 GB 下载全部启用。不扩展为 DICOM 诊断工作站、多医院云产品或通用流程平台。

## 3. 领域、数据与接口设计的阅读方法

正式拓扑保持 Windows Server / Nginx / Spring Boot / PostgreSQL 16，拓扑和依赖边界以 [ARCHITECTURE.md](../../ARCHITECTURE.md) 为准，详细业务与部署说明见[内部架构文档](../../vitepress-doc/internal/architecture.md)。正式部署不依赖 Docker。

| 设计面 | 现有事实/机制 | 后续设计要回答的问题 |
| --- | --- | --- |
| 病案与扫描 | 病案主档、扫描记录、编号解析与现有查询分页 | 关联是否唯一、原始编号是否保留、失败是否可区分、有无大表扫描或超时证据 |
| 影像与来源 | 统一内容网关和本地/NAS/Nginx/OSS 适配 | 混合来源、缺失文件、响应中断、来源切换和错误脱敏如何验证 |
| 导出 | 既有后台任务、配额、取消、过期、Range、清理和恢复 | 所有下载入口是否遵守预算，任务所有者、重下与失败回退如何保护 |
| OCR 与分类 | 已有事实、建议、审核、正式类型和批次 | 人工修改保护、授权、审计、离线模型质量与适用范围是什么 |
| 实体位置与归档 | 现有装箱/位置能力；完整生命周期仍待实施核对 | 生命周期、文件状态和实体位置怎样分开，归档凭什么确认 |
| 账号、审计与运维 | JWT/RBAC、撤销、访问审计、诊断、维护与恢复工具 | 拒绝路径、跨会话隔离、重启、故障与恢复有哪些实际证据 |

字段及接口必须以当前 Mapper/迁移、DTO/Controller、测试和运行中的 OpenAPI 核对。本文不另列一份容易漂移的完整字段字典或接口清单。修改已发布 Flyway 迁移、猜测唯一性或开放任意 SQL 都不属于文档整理可以批准的行为。

改变依赖方向、权限、外部票据、数据不变量或基础设施时，先按 ADR 与高风险提案流程处理；不能通过设计文档直接引入新 API、Store、队列或数据库。

## 5. 每次设计变更的交付内容

先提供问题证据、当前调用链、目标/非目标和不变量，再列出模块/文件、接口/表/配置影响、最高风险、验证方法、独立审查及关闭或恢复步骤。业务与 UI 设计分别更新对应事实源，避免把工作记录堆进架构总图或公共组件规范。

界面变更按 [前端规范](../../frontend-fantastic-admin/DESIGN.md) 验证字段含义、状态、键盘、宽窄屏、明暗主题和兼容降级。事务、迁移、复杂 SQL、锁与大表行为使用 PostgreSQL 16 证据。医院原始数据、账号密钥与现场记录留在院内，仓库只收脱敏结论、范围、SHA 和证据编号。

首轮候选使用同一固定 SHA 与制品完成适用 CI、Windows 和医院副本验收；未验收能力保持关闭。不得回退到缺少持久化 Token 撤销保护的旧应用；恢复策略服从 [发布基线](../../release-baseline.json)，数据库仅以前向新增迁移修复。

纯文档变更核对来源文件、Markdown 链接、版本、关键数值和既有治理检查；不为文档启动应用或把未执行的业务测试写成通过。
