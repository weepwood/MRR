## 实测结论

桌面标题均 26px/700，正文表格 13px、表头 12px；经典表头42/常规行46，暖色38/40；权限表格38px（保留专用密度）。普通输入/按钮经典33、暖色30；原业务单值选择器均32px。记录/患者/装箱可见标签12px/600，日志/审计12px/500且 muted。经典 desktop header 高度76/100/126 等，取决于眉题和元信息；不能据高度一律判错误。120 组文档及采样共享容器无横向溢出，表格内部横滚有意保留，不等于全页内容无任何裁切。

## 实施及待决策

- P0 单值筛选高度：复用 mrr-single-select，六页面11处直接选择器及 MrrUserSearchSelect 两个调用，共13处实际实例。保留多选、筛选值、检索及远程用户名行为。严格断言33/30px，第一次复验漏共用用户名组件，17/21通过，四组视觉调查因该漏项失败；补齐后联合21/21（1.4m），120组复验及120 PNG，156个实际选择器高度采样（经典78个33px，暖色78个30px），0处所测容器溢出；日志/tmp/mrr-v12-business-final2.log，证据/tmp/mrr-v12-business-visual-final。
- P1 标签：保留 labelled、grid 与 compact 无标签用途，统一同类可见标签字重/颜色/间距，保留 label-for 与 aria。
- P1 查询操作：优先复用 MrrFilterActionButton，用户页已有异步动作状态不可丢失；确定每个操作区 primary 规则，不把记录页批量下载与查询混同。
- P1 记录原生匹配方式 checkbox：采用 ElCheckbox，保持提交/翻批/reset 与键盘。
- P1 表格详情入口：运行错误中心和日志/记录统一查看语义，图标/文字选择需统一，保留危险操作；用户表无条纹与其他条纹表的差异需统一评估，不强制全部 stripe。
- P1 页头眉题：定规则，统一标题起点；不盲目补英文，允许元信息及说明自然换行。
- P1 审计五指标 4+1：根据内容宽度和最小卡宽优先均衡五列，窄屏换行，勿全局改动其他四指标布局。
- P2 日志/审计筛选：desktop 充分利用网格，手机可考虑保留关键字/时间等首要项、其余折叠并显示已应用条件；不能默认隐藏已生效条件，改布局前需交互回归。

保留两套配色及业务布局差异，不对真实数据执行操作。
