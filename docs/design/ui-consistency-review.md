# UI 与交互一致性评估

核对日期：2026-11-11。基线 `main@bbaf95c4`，本轮实施关联 [#559](https://github.com/weepwood/MRR/issues/559)，风险 P2。本报告描述仓库和合成 Mock，不代表医院终端验收。

## 结论与依据

继续沿用现有中性管理端：颜色、字体、圆角、33px 控件和明暗主题由现有令牌及设置驱动。当前主要问题是旧页面对共享结构的采用程度不同，不需要重新建立主题或改变业务信息架构。

源码检索发现 19 个 Vue 文件包含旧 `class="page-header"`，4 个文件使用 `MrrPageHeader`；这是文件匹配数，包含嵌套内容，不等同于路由数量或缺陷数量。全局样式已经统一旧页头字号、部分窄屏表单和分页，不能把旧类名直接当作故障。

独立评估 A 从源码检查任务和设计；评估 B 独立运行 detector，并在三页（日志、影像审计、用户）× 两主题 × 两视口（1440/375px）下读取布局、标签、焦点和截图。源码 detector 为 0 项，但浏览器仍发现日志详情裁切，因此静态扫描只作为补充。

| 问题 | 已确认事实 | 处理 |
| --- | --- | --- |
| 页面层级 | 两个查询页以 h2 作主标题，共用页头和用户页使用 h1；视觉字号原本已一致 | 使用共用页头，保留原标题、说明及操作 |
| 筛选排列 | 查询页使用侧置标签和各自的控件宽度，字段与按钮混排；现有标签大多已经正确关联 | 统一上置标签、字段排列、独立动作区，保留字段顺序和条件 |
| 结果分区 | 日志无结果标题，审计明细使用自定义标题/计数/分页容器 | 使用已有数据面板与分页插槽 |
| 页面节奏 | 日志/审计局部间距为20/18px，共用壳默认24px且有最大宽度 | 使用共用页面壳，移除重复样式 |
| 日志详情 | 768px 下 dialog 实测 clientWidth 758、scrollWidth 900；375px 内部 descriptions 仍溢出 | 视口宽度约束、窄屏单列、长文本换行与固定表格布局 |

保留的优点：查询/重置主次明确，失败与空结果分开，筛选条件完整，表格有自身横向滚动。高频操作者需要稳定的字段扫描顺序；键盘用户需要可见标签和真实焦点，不能通过隐藏条件或扩大权限简化界面。

## 本轮统一规则

视觉事实仍以 [前端 DESIGN](../../frontend-fantastic-admin/DESIGN.md) 为准。本轮分支使用以下既有组件及增量约定：

- `MrrPageShell` → `MrrPageHeader` → 筛选/内容 → `MrrDataTablePanel`，页面主标题 h1，分区标题 h2。
- 少量条件沿用 `MrrFilterBar` 默认 inline；多条件可用 `layout="grid"`，包在 `label-position="top"` 的 `el-form` 内，默认行为不改变。
- grid 字段在桌面为三列、1100px以下两列、760px以下一列；日期范围项使用 `mrr-filter-bar__range` 跨两列，窄屏回到单列。使用现有间距与控件令牌。
- 查询/重置放在 actions；日志筛选仍位于结果面板，审计筛选仍位于分析与明细上方，保持作用域可见。
- 分页复用数据面板插槽和全局窄屏布局。表格横向滚动，不让页面本身承受大表宽度。
- 弹窗使用视口上限；窄屏详情单列，长 URI 和预格式文本可读。Teleport 内容的样式使用页面专属全局选择器，需验证实际计算样式。

查询参数、Request ID 预填、Enter、刷新、重置、分页、详情读取回退、审计统计代次隔离和全部导出入口保持原语义；本轮没有接口、表、权限、依赖或部署变更。

## 渐进统一顺序

| 页面族 | 后续检查与复用 | 必须保留 |
| --- | --- | --- |
| 日志与审计查询 | 本轮建立筛选、结果、详情的可复用基线 | 查询/分析联动、拒绝/错误/空态、导出作用域 |
| 运行日志、错误中心、诊断 | 先核对列表/筛选结构和恢复入口，再逐页复用 | 故障提示、请求追踪、缺口与恢复状态 |
| 扫描记录、患者、装箱 | 分别核对游标/普通分页、选择操作、编号显示 | 编号原值、选页范围、批量操作与原有权限 |
| 统计与响应分析 | 继续复用图表/分区卡，统一说明与空错误态 | 指标口径、分母、更新时间和加载失败 |
| 存储、导入、系统设置 | 按任务检查长路径、表单分组、确认和反馈 | 配置来源、敏感操作确认、关闭/恢复步骤 |
| 档案袋 | 独立验收工具栏、图片状态、打印和导出反馈 | 页面顺序、选页、取消、资源释放、下载预算 |

每批先复现具体问题，再以单一目标 PR 实施。上述后续项尚未逐页验收，不把源码匹配结果等同于全站已统一，也不采用其他工作区未确认的重设计方案。
