# 档案袋导出代码审查与结构优化

## 范围与结论

关联 #523，风险 P1。调查基线 main `d66235c3`，同时核对 #517、#520、#522 的差异。本次深入审查档案袋选页、打印与导出调用链；对迁移页面和服务只做职责调查，不声称已审完全部业务、权限或 SQL。

继续保持模块化单体和现有分层。当前优先问题是异步操作与页面选择的生命周期脱节；目录重排不能解决这个问题。先修复可复现行为，再按业务职责拆分，避免同时建立新的请求、Store、任务状态或缓存机制。

## 已确认的问题与修复

旧链路为 `archive.vue → useArchivePrint → 规划 API → 客户端合成 / 同步下载 / useArchiveExportJob`。

- 失效逻辑仅在任务对象已存在时执行，规划或创建未返回时切页，旧请求仍会创建或回填任务。
- 合成和同步下载返回后直接保存；切页或离页仍能保存旧 PDF。
- 旧请求的错误和 finally 没有有效期校验，会显示过期错误或结束新请求的 loading。
- 规划后的客户端合成读取原影像对象，等待期间对象变化会使规划 IDs 与合成 URL 不再属于同一快照。

首批 12 项回归在修复前全部因行为断言失败，不把测试环境缺失的 URL API 错误算作 RED 证据。覆盖三种规划分支、迟到任务取消、切页/离页、过期错误、新旧 loading、重复点击和快照。独立审查后另补创建期间离页、旧创建与新任务并发两项，14 项新测试与原有 8 项相关测试共 22 项通过。

续优化又复现了全局选择事件的实例耦合：B 改选或初始化能误清除 A 的 PDF 任务。新增 5 项实例隔离测试在旧 PR 提交上全部行为失败；生产页面现将既有 `selectedItems` 只读 Ref 传入打印/PDF 编排，PDF 使用同步 watch。移除 window 的选择广播与消费，不增加 Store、事件总线或任务机制。原 14 项异步回归改为真实 Ref 驱动，继续保留；无参打印/显式 PDF 调用保持兼容，但不再接收全局事件。新增与相关回归共 28 项（含原 useSelection 用例）通过。

修复后的职责：

| 模块 | 唯一主要职责 | 保持的边界 |
| --- | --- | --- |
| `archive.vue` | 展示与操作入口 | 注入所属页面的 selectedItems，既有返回字段与按钮行为兼容 |
| `useArchivePrint` | 打印文档、影像等待和打印框架 | PDF 返回字段委托给新模块，原生打印本批不改 |
| `useArchivePdfExport` | 选页快照、规划和执行结果的有效期 | 规划、创建、客户端合成、直接流的返回检查当前操作；过期结果不保存、不提示、不修改新状态 |
| `useArchiveExportJob` | 后台任务、轮询、取消和迟到创建清理 | 继续复用 discard；新模块不复制后台状态机 |
| `api/modules/archive-export` | 统一鉴权请求与协议 | 无第二个请求实例或新接口 |

选择变化时即使尚无任务对象，也推进已有任务机制的失效代数。离页时丢弃绑定任务；非终态任务沿用现有取消 API，取消失败仍由服务端任务过期/清理兜底。原图、医疗数据和数据库均不修改。

独立审查另复现了既有共享下载工具缺口：任务已经 SUCCESS 并开始 Blob 下载后，切页虽然清空任务，下载结果仍可能保存并显示成功。该问题涉及自动/手动下载与 Range，单独由 #524 跟踪。本批有效期保护不涵盖已经开始的任务文件下载，不能宣称全链路已消除迟到副作用。
