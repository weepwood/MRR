## 问题与职责

通用 useCrudList 在旧响应较晚返回时会覆盖新list/total；旧finally会提前清除新loading。logs、audit-images还在fetchApi内写页面错误，且直接return Promise使异步失败绕过try/catch。审计页并行统计同样没有版本检查；只修列表会留下与当前列表不一致的统计或旧错误。

最小修复继续使用原列表composable：每次loadData推进generation，只有当前实例/代数能回填结果和结束loading，过期失败不再传播给新请求。当前未处理异常仍抛出，保留已有行为。作用域释放使代数失效并阻止后续请求；一参fetchApi兼容，第二参新增只读isCurrent上下文供既有页面保护自己的错误状态，不传入HTTP参数。

两页面await原API后捕获异步失败，只有当前请求更新错误；当前403/500仍显示错误与重试，不伪装为空结果。审计统计保留独立请求，用页面内版本与销毁检查保护数据、错误和loading；不增加Store或网络框架。搜索、分页、每页数量和重置继续使用原参数及默认值。
