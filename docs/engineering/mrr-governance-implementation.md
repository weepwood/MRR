# MRR 数据治理实施任务包

风险等级：P1。关联 #109、#111、#137、#142、#99。

## 问题与证据

基线 main 1c698081：Java/TypeScript 自动补零与数据库保留原值冲突；扫描触发器更新编号后可能保留旧关联；root 日志采集被非传播 logger 绕开；错误写库失败会丢失；诊断包含存储细节；Token 撤销仅在内存。

## 目标

查询正确且可说明原因；前端通过 Request ID 关联诊断、访问日志和错误；实际产生的全级别日志脱敏后长期入库，数据库故障可补录；数据质量和性能有证据。

## 非目标和不变量

不引入新的服务、中间件或生产 Docker；不猜测患者与就诊关系，不自动合并/删除病案；不修改历史迁移，不重写原始编号和存储路径。无权限不得读取或探测病案；普通日志和报告不得包含患者数据、凭据或内部路径。

## 建议方案与影响模块

分批 PR：编号与关联正确性；日志及诊断隐私；Token 撤销持久化；查询诊断与页面；可恢复运行日志；数据质量和查询性能；UI、运维及验收文档。后续 PR 在先决 PR 之上堆叠，每次差异保持单一目标，按依赖顺序合入 main。

扩展现有 ScanService、运维/关系工作台、错误中心和统一 Axios，不建立平行认证和错误处理。数据库使用新增前向迁移。新跨域日志能力先有 ADR。

## 替代方案与取舍

同步写日志会使业务受数据库故障拖累；只用内存队列无法恢复。采用脱敏结构化文件及持久化采集断点。有限磁盘不承诺无限保存：不自动删除入库日志，缓冲满时优先业务并报告缺口。

## 验收标准和验证计划

- 编号保留原值；兼容查询歧义时明确失败；修改编号后不保留错误关联。
- 权限拒绝无存在性信息；日志与诊断不泄露敏感数据；重启不恢复已撤销 Token。
- 日志轮转、重启、数据库中断及重复补录后不重复入库；前端显示延迟、容量和缺口。
- PostgreSQL 16 验证迁移、触发器、游标、事务与恢复；Vitest/E2E 验证竞态和状态；Windows PowerShell 5.1/Chrome 86 验证关键流程。
- 性能目标：采集开启后的业务 P95 开销不超过基线 10%；等量副本记录查询计划及增长率。现场证据缺失时保留待验收，不声称已达标。

## 回滚与数据修复方案

代码按 PR 独立回退，安全修复不回退到泄露状态；新增表保留数据，结构问题只前向修复；日志和深入诊断可独立关闭。历史数据修复先 dry-run，唯一候选才可分批处理，并保存旧值、批次、操作者和恢复清单。

## 数据与隐私确认

仅使用合成测试数据；生产验证在院内执行，日志、截图、Issue 和报告必须脱敏。不提交本地配置或密钥。保留原工作目录现有未跟踪文件。

## 验证记录

实施过程中记录 RED/GREEN、实际命令、结果、独立审查与剩余风险；医院现场查询失败根因和三千万级性能仍需院内证据。
