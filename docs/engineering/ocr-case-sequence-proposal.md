# 历史 OCR 逐案与上下文建议实施任务包

关联 #417、#342；风险 P1。2026-10-25 用户授权实施。

## 已确认事实与范围

历史队列当前按 scan id 分 200 页再按 archive_id 分组；单案可被拆开，任务按 scan_id 领取。
用户确认有效上架号为 `COALESCE(NULLIF(BTRIM(sjh),''),NULLIF(BTRIM(bah),''))`。
该值只用于分组与显示；不回写编号，不改变存储路径。有效编号冲突或主档归属不一致时阻断，
不合并不同主档。保留编号前导零。沿用现有权限、OCR事实、队列、租约和类型审计。

## 文件计划与验证

1. OcrBatchService/OcrBatchMapper：新批次逐案登记，全局历史任务串行，固定 ID 范围，
   已登记病案不重复登记。单案超过额度、被范围截断或有效编号冲突时给明确原因。
   PostgreSQL 测试先证明超过200页整案、反向页序、预算和恢复行为。
2. OcrMapper/OcrModels/OcrJobService：登记时固定 pages 和顺序；按顺序领取；退避页仍属待处理，
   OCR全部结束后逐页完成第二遍上下文分析，检查点持久化，事务不跨IO。
3. ClassificationEngine/ClassificationService：仅在明确连续证据下从独立标题参考页生成建议，
   有限传播、缺页/重复页/新标题/失败/不同类型阻断；疑似正反面只做关联建议。
   所有上下文建议 autoEligible=false；参考页变化时审核拒绝。原文不改写。
4. 现有历史页/API/ClassificationReview：病案份数、页序、依据、相邻页并排核对与关系审核。
   分页和图片Blob有界，复用统一请求与权限；Vitest/Playwright、类型、构建和Chrome86检查。
5. 新增前向Flyway扩展任务、页面和建议元数据及有效编号索引；旧任务保留旧模式。
   PostgreSQL16验证迁移、幂等、锁、源/类型/参考页变化与权限失败，运行仓库治理命令。

## 不处理

不引入队列/云OCR/外部服务；不做全文搜索、模型训练、历史归属修复、已分类页面重识别、
无依据的奇偶配对或整案一键改类。原有单页自动准入条件不放宽。

## 验收与回滚

一份病案OCR、上下文分析和自动应用结束（或降级人工）后才能登记下一份；人工审核不阻塞。
失败页保留原因；暂停、取消、撤权和资源窗口沿用现有边界。
不在内存无界加载病案图片或OCR正文；每轮上下文分析只读取有限相邻页。
关闭OCR并暂停/取消批次后维护；保留事实、建议和审计，正式类型按既有受保护回退执行。
当前发布基线已禁止整体回退到缺失持久化Token撤销的旧版，因此本次回退采用本功能提交的
安全前向撤销，不修改既有发布回退政策；数据库结构保留，以前向迁移修复。

## 未知项

生产页序质量、单案规模、正反面准确性及索引计划须院内验证。本地测试只使用合成数据。
新规则不继承旧自动分类验收结论；部署与代码完成不等于生产识别质量验收。
