## 1. 当前功能与边界

| 链路 | 已有实现 | 边界 |
| --- | --- | --- |
| Nginx 入口 | 请求编号、状态、上游耗时和入口审计文件 | 可记录未到应用的请求；与应用日志分别核查 |
| 应用访问审计 | `LogInterceptor` → `AsyncLogServiceImpl` → `app.access_log`；按用户、接口、请求编号等查询，影像访问统计与受控导出 | 当前为内存缓冲和重试，不保证数据库持续故障、强制退出时不丢失 |
| 运行日志 | `PrivateJsonLogEncoder` → 脱敏 JSON 文件 → `RuntimeLogJournalService` → 月分区明细与来源断点 | `app.runtime-logs.enabled` 默认关闭；启用前须副本验收。正文只允许审核模板，不展开任意参数或异常消息 |
| 运行错误中心 | WARN/ERROR 聚合、错误编号、追踪编号、处理状态；新日志链路使用同一事件流投影 | 聚合不能替代原始事件；旧格式补录不重新累计无法可靠关联的历史错误 |
| 查询诊断 | 通过 Request ID 关联访问、病案查询阶段和当前只读探测 | 无日志不等于请求未到达；当前探测不能重建过去数据库状态 |

运行日志查询复用已有统一 API：默认24小时，单次最多31天，游标时间与事件UUID成对传递，服务端最多200条及3秒查询超时；页面每批50条。运行日志页要求 `system:manage` 与 `log:read`，补录另需 `system:log:import`，后端才是授权边界。

隐私沿用 [ADR-0002](../adr/0002-recoverable-private-runtime-diagnostics.md)：普通参数按白名单留存；凭据、身份和未知字段隐藏；业务编号使用独立密钥的HMAC检索摘要。未配置密钥时不能退回普通哈希。历史读取也做脱敏，不承诺旧日志原文检索。查询、截图、Issue和测试只使用合成数据。

## 2. 本轮问题与处理

| 已复现问题 | 分支中的完善 | 验证 |
| --- | --- | --- |
| 健康与文件清单共用 Promise.all，任一失败丢弃另一项成功结果，且覆盖列表 error | 三个区域分别表达失败；健康/清单独立提交结果，保留上次成功数据并标记读取失败 | 健康失败日志仍可读；清单失败健康仍可见；原查询错误不被覆盖 |
| 下一批请求前修改 cursor，失败重试却重新提交草稿并回首批 | 成功后才提交游标；失败重试原已提交参数和目标游标；刷新日志与回首批沿用已提交条件 | 对比请求时间、筛选、游标；点击查询日志才应用草稿；清空时间后提交会明确恢复并固定最近24小时 |
| 状态刷新缺少代次和卸载失效保护 | 最新状态请求获胜；卸载后不回填，不继续发起下一文件登记或状态刷新 | 延迟成功、失败及卸载期间请求测试 |
| 多文件登记部分成功仍保留全部选择，重试重复成功项 | 固定本批选择范围，逐项移除确认成功文件；失败及未尝试项保留；阻止重复提交 | 请求序列与剩余选项验证 |
| 登记与后台入库容易混淆 | 明确“已登记”不代表完成入库；失败项称“未确认登记”，不推断网络错误是否发生在服务端提交前 | 页面数量、反馈与实际请求一致 |

文件清单读取失败或刷新中暂不允许登记；健康读取失败本身不会隐藏已查日志。请求失败后使用“刷新状态”恢复健康/清单，使用日志区域的“重试”恢复查询，互不替代。

本轮不引入新的 Store、请求实例、通用任务平台或日志后端。查询代次沿用本页已有机制，并参考 `useCrudList` 的卸载失效约定；固定范围游标分页不能直接改成普通页码分页。
