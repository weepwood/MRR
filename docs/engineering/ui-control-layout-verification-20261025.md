# 控件间距、宽度与裁切问题验证记录

日期：2026-10-25。风险等级：P2。关联方向：Issue #89、现有 UI 分支及 PR #396；本轮不宣称完成 Issue #89 的全部设计系统迁移。

## 范围与调查

用户要求审查并修复控件间距、重叠与宽度问题。先只读检查架构、前端工程/设计规范、现有组件和调用关系，再通过 Playwright 实际渲染定位。使用独立布局评估与机械评估，避免把静态候选直接当成缺陷。

巡检 20 个页面的 1366、1024、768、375px 四档布局；另独立检查全部 11 个设置分类、明暗主题、配色编辑行、外观配置抽屉和日期弹出层。所有数据来自 Mock 或测试内存状态，没有访问医院真实数据。机械布局扫描修复前后均为 `[]`，实际缺陷由截图、控件边界和真实操作确认。

复用现有 `.page-shell`、Element Plus、设置网格和主题令牌。未新增依赖、请求、Store 或定位框架。没有修改查询口径、保存逻辑、权限、审计、数据库、存储或部署方式。

## 确认的问题与修复

| 问题与实测证据 | 修复位置与结果 |
| --- | --- |
| 日志日期范围在 375px 下从 x105 延伸到 x463；历史日志下拉同样越界 | `form-controls.css` 让窄屏行内表单的标签后内容可收缩，约束输入、日期与数字控件最大宽度 |
| 数据交换、统计明细和接口测试页面被网格最小内容宽度撑开，外层 `overflow:hidden` 隐藏右侧控件 | `base.css` 的既有页面壳、数据交换内层网格及接口测试根网格使用 `minmax(0,1fr)`，保持内容区内排版 |
| 患者、日志等既有分页没有共享数据面板的窄屏布局；游标分页控件与文字紧贴、垂直错位 | 分页布局提升到 `element-plus-overrides.css`，共享数据面板删除重复规则；记录页保留完整翻批导航组并统一 8px 间距 |
| 明示 `gap` 的操作组仍叠加相邻按钮 margin | 仅对 header/filter/section 三类显式操作组清零重复左边距，普通行内按钮仍保留原有间距 |
| 1024px 设置双侧栏后内容很窄，双列控件与滑块被压缩；OCR 标签、数字和百分比并排，单项需要 240–309px | 设置网格按实际容器自动排列；OCR 使用现有顶部标签表单，保留全部参数与单位 |
| 科室配色编辑区在 1366px 时仅约 689px，五列却至少需要 780px，删除按钮被裁；1024px 头部 416px 固定按钮组把说明压至约 26px | 头部按钮可换行，编辑行提前折行；隐藏列头时显示“档案袋主色/顶部色条”字段标签并补输入名称 |
| 外链表单至少需要 592px，1024px 设置内容不足导致添加按钮不可见 | 表单按容器宽度自动排列，名称、地址、添加操作均保持可见 |
| 外观摘要与自动保存提示重叠；1024px 配置行宽约 367px、内容约 393px，输入被裁 | 摘要与设置行可换行，输入受容器约束；手机竖排及外观抽屉重置横排 flex-basis，避免产生 260px 空白 |
| OCR 规则权重列宽 105px，默认数字输入宽 150px，被单元格裁切 | 通用数字输入最大宽度受容器约束；实测输入为 81px，可完整显示允许值 1000 |
| 日期范围展开后仍约 648px 宽；只限制高度时，短窗口内整个弹层仍被放到视口下面；嵌套时间面板又向右越界 | 两月上下排列并限制视口尺寸；8 个范围入口共用 `ui/provider/picker-options.ts` 的现有 Popper 纵向避让配置；时间面板右对齐，保留日期、时间及两级确认 |

表格自身的横向滚动和桌面设置右侧的纵向滚动属于正常布局，予以保留。没有用隐藏操作、缩小文字、放宽权限或删除断言解决问题。
