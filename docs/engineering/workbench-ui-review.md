# 共享 UI 与数据关系工作台优化

关联 #533，风险 P2，基线 main d66235c3。用户确认优先共享组件与工作台；沿用现有 DESIGN.md 和 Operate 模式，保留蓝色主操作、明暗主题、33px 控件、标题与所有业务文案。未更换视觉体系或引入新组件库。

本轮深入检查数据关系工作台、MrrPageHeader、MrrMetricCard 及相关样式；不声称全仓 UI 已完成审查。两个独立上下文分别进行设计评估和检测/浏览器证据评估，另有独立代码审查。全部浏览器数据为合成 Mock，无真实患者或医院后端访问。

## 设计分析与已实施内容

| 观察与证据 | 优化 |
| --- | --- |
| 指标→三个任务标签→结果表的层级清楚，估算与只读说明有用 | 保留任务顺序与文案；使用共享页面壳和页头，标题统一为 h1，复用四指标网格避免中等宽度出现3+1 |
| 共享无图标指标在375px时被移动端双列规则覆盖，正文压成约40px窄列 | 双列移动样式只应用有图标卡；无图标仍占整行。先写浏览器宽度断言，在旧样式失败后修复 |
| 千万计数在关系卡三列中相互挤压 | 计数网格按可用宽度排列，使用等宽数字并允许必要断行，保持字号 |
| 中间宽度下标题说明和异常筛选争抢空间，输入内容截断 | 页头与筛选组允许换行，输入保留合理宽度；窄屏垂直排列且不把 flex-basis 当作高度 |
| 部分输入只有 placeholder，无可访问名称 | 为查询值、异常级别及关键字提供稳定 aria-label，保留可见提示 |
| 独立检查发现375px加载病案详情后内层栈被表格撑至842px | 栈使用 minmax(0,1fr)，分区可收缩，保留表格内部横向滚动；详情分区增加统一间距 |
| 固定520px抽屉超出窄屏；100vw还会包含滚动条宽度 | 限制为 min(520px,100%)，按实际容器收缩，375px检查抽屉宽365px、x=0 |

共享页头保持原 props/slots，增加可收缩与换行约束。未修改 API、权限、查询和检查状态、筛选语义、修复预览只读边界或默认移动适配设置。没有通过隐藏按钮或表格列来解决溢出。

- 新 `e2e/workbench-ui-layout.spec.ts` 定向覆盖无图标指标、1366/900/768/375宽度、字段名称、明暗主题的真实查询详情及抽屉；4项通过。
- 原工作台单测保留全部标题和只读说明断言，注册真实共享页头/页面壳；新增刷新/执行检查按钮接线回归，3项通过。按钮桩声明click事件，避免原桩原生冒泡造成假双击。

- 检测器运行一次，报告原有病案标题卡4px左边框；此为既有设计，不因机械提示改动它。
- 类型、变更 ESLint/Stylelint、生产构建、Chrome86静态、仓库治理及当前SHA CI结果记录在PR。现代Chromium视觉验证不能证明真实Chrome86或医院现场通过。
