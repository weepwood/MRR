# 影像档案袋水印用户名与 ID 设计

## 目标

将影像档案袋的登录用户水印从单一用户 ID 调整为 `用户名-ID`，例如 `br_admin-1`，以便在截图、预览和全屏浏览中同时识别账号与数据库用户。

## 范围

- 仅调整影像档案袋全局访问水印的用户标识文本。
- 保留现有水印时间、透明度、斜向平铺、分钟刷新和开关行为。
- 不修改外部影像档案袋、PDF 导出内容、图片文件或后端接口。

## 取值规则

水印用户标识按以下优先级生成：

1. 当前路由 URL 含非空 `userid` 查询参数时，直接使用该参数，并覆盖登录用户信息。
2. URL 不含有效 `userid` 时：
   - 用户名和 ID 同时存在：输出 `用户名-ID`。
   - 只有用户名：输出用户名。
   - 只有 ID：输出 ID。
   - 用户名和 ID 均不存在，但账号显示值存在：输出账号显示值。
   - 所有候选值均为空：输出 `未登录`。

字段在参与拼接前统一转换为字符串并去除首尾空白。缺失字段不生成多余连字符。

## 实现边界

- `archive-watermark.ts` 负责根据用户资料和账号显示值生成水印标识。
- `archive-watermark-installer.ts` 保持 URL `userid` 的最高优先级，并仅在该参数为空时调用水印标识生成函数。
- 不新增状态、接口请求或配置项。

## 测试设计

在现有 `archive-watermark.test.ts` 中使用真实辅助函数覆盖：

- 用户名和数字 ID 生成 `doctor-42`。
- 用户名和字符串 ID 会去除首尾空白后拼接。
- 仅用户名、仅 ID、仅账号和完全缺失时正确回退。
- 现有时间格式、开关解析和透明度边界测试继续通过。

URL 覆盖逻辑保持现有实现，不改变其输入输出；代码审查确认 `routeUserId(router) || resolveArchiveWatermarkUserId(...)` 的优先级不被调整。

## 验收标准

- 登录用户资料为 `{ username: 'br_admin', id: 1 }` 且 URL 无 `userid` 时，水印第一行显示 `br_admin-1`。
- URL 为 `/archive?userid=external-7` 时，水印第一行显示 `external-7`。
- 用户资料字段缺失时按既定规则回退，且不出现 `undefined`、`null` 或多余连字符。
- 相关 Vitest 测试、TypeScript 类型检查和前端构建通过。
