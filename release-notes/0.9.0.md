# MRR 0.9.0 发布说明

0.9.0 汇总公开版本 v0.8.0 之后合入主线的功能、安全、可靠性和界面改进。正式源码提交、构建 run 与制品摘要由 Release 工作流生成并绑定；本文不代替医院现场验收。

## 主要更新

### 病案查询、权限与影像访问

- 保留病案号和上架号原值，收紧精确/兼容匹配与歧义处理，更新编号后的主档关联，并为旧查询和数据质量探测增加执行时限。
- Token 撤销持久化，收紧注册默认角色和管理员保护；历史日志读取与请求诊断遵守隐私边界。
- 内部及外部受保护影像使用受控内容网关；迁移至 AWS SDK Java v2，并修复 OSS 签名有效期和来源流并发名额归还。
- 登录注册、环境诊断、账号间档案袋历史及迟到响应隔离得到修复。

### 导出与打印

- 内部 ZIP 复用后台任务，完善配额、取消、清理、重启恢复与队列暂满后的重试，减少重复准备和元数据读取。
- 浏览器每文件导出预算为128MiB，超限提示分批；选页和旧响应隔离、生成成功后的下载失败恢复得到完善。
- 单次打印限制为50张。以上预算是当前软件限制，不能代替目标终端资源与真实 Chrome86 验收；完整多GB下载仍属后续专项。

### OCR、分类与数据运维

- 增加离线 OCR 持久化任务、规则/词库版本、审核审计、可暂停续跑的历史批次及受控自动应用机制。
- OCR事实、分类建议和正式类型分离；既有分类及后续人工修改仍受保护。OCR、自动应用和历史批次须按现有开关、授权及质量门槛启用，不因升级自动放开。
- 增加请求诊断、运行日志文件断点与幂等入库、错误投影、运维运行看板、只读降级及 Windows 恢复工具；默认关闭的新运行日志采集仍须副本验收后启用。

### 本轮界面与日志恢复

- 统一共享页面头、图表卡片、用户筛选标签、日志/影像审计筛选和结果面板，完善明暗、窄屏、焦点及详情长文本；侧栏子目录点击不显示涟漪。
- 运行日志查询、健康和文件清单失败分别展示；重试使用原已提交条件及游标，刷新不提交草稿，空时间查询固定最近24小时。
- 多文件补录逐项移除确认成功项，保留未确认项重试并阻止重复提交；明确登记成功不代表后台完成入库。
- 补齐根设计入口、页面蓝图、交互验收矩阵，以及日志分析与医院上线准备度台账。

工程继续使用 Windows Server、Nginx、Java21/Spring Boot4、PostgreSQL16 的模块化单体；生产不依赖 Docker。前端、后端与发布工具链升级以本版本锁文件和 Maven 配置为准。

## 数据库、升级与恢复

- 当前最低兼容迁移：`20260715113552`；最高兼容迁移：`20261018102000`；配置结构版本：`1`。
- 相对 v0.8.0，新增10个正式SQL迁移，涵盖注册角色、OCR执行/审核/批次、扫描关联、Token撤销、错误投影收据和运行日志。此版本准备提交不改写既有迁移，不执行医疗数据修复。
- 升级前备份数据库、影像、受保护配置与密钥，核对 Flyway 历史；按 [医院副本验收包](../docs/engineering/hospital-replica-acceptance.md) 演练升级与恢复。维护 OCR 前关闭相关能力并暂停批次，保留已发生的正式分类与人工修改。
- **禁止直接回退旧应用，包括公开 v0.8.0。** 当前 `release-baseline.json` 的 `backwardCompatibleWithPreviousApplication=false`、`applicationRollback.allowed=false` 继续生效。旧版本缺少持久化撤销等保护，故障优先关闭新功能或安全前向修复；数据库仅新增前向迁移，撤销、审计、日志明细/断点和错误收据保留。
- 不依据旧版说明或阶段性 ADR 中的历史回退描述覆盖当前发布基线。

## 验证与已知边界

正式发布仅在固定 main 提交的集成检查通过后执行已有 Release 工作流；完整验证包含后端单元/PG16集成、前端单测/覆盖率/构建、Mock与真实后端浏览器流程、候选JAR身份及实际 Windows PostgreSQL备份恢复演练。具体结果以该次 Release run 为准，不将候选或局部门禁通过写成发布已完成。

本轮合并涉及设计文档 #558、UI #560、运行日志 #563；既有单项验证和独立审查见对应PR。正式验收针对包含全部改动的同一发布提交和同一候选制品重新进行。

- 访问审计仍为内存缓冲及重试，数据库持续故障或强制退出时可能丢失，耐久性完善由 [#102](https://github.com/weepwood/MRR/issues/102) 跟踪；运行日志文件机制不能替代访问审计完整性。
- 运行错误中心的请求隔离由 [#562](https://github.com/weepwood/MRR/issues/562) 跟踪；生命周期历史实现追溯及其他后续能力不因版本提升视为已完成。
- 真实医院数据质量、千万级性能、Windows/Nginx/NAS/OSS、实际 Chrome86、容量和恢复目标仍由 [#350](https://github.com/weepwood/MRR/issues/350) 现场负责人验收。CI使用合成数据，不能替代医院生产启用确认。
- Chrome86静态构建检查允许已注明的依赖装饰性降级；不等同于真实浏览器验收。
