# MRR 1.0.0-rc.1 候选说明

本版本是 V1.0 发布候选，不是正式生产发布或医院启用批准。候选源码身份由实际合并提交及同一轮完整 dry-run 的 run/attempt/manifest 记录；不得将旧版本预演结果作为本候选通过证据。

## 候选范围

- 病案编号精确检索、游标与明确兼容包含查询；三千万合成实验支持精确表达式索引，旧包含 COUNT 存在超时，默认不部署 GIN。真实服务器容量、索引就绪和回滚仍须现场预检。
- 多来源受控影像、Range、正文超时、节点与全局资源许可、半开探针、实际关闭回收；档案导出所有者、下载配额和取消恢复。
- 运维总览索引就绪及容量、NAS/HTTP/Nginx/OSS 节点状态、SDK 池最近采样、进程内有界异常事件及趋势。重启清空，不能替代持续监控或持久审计。
- 身份证查询兼容迁移（#799 已合并 e0ac2036）：患者新增 POST，扫描页普通查询改用 POST 和内存传参，保留旧 GET 和合法旧深链。既有外部 HMAC、Ticket、加密协议及权限不变；旧深链、历史 URL 与定制代理日志仍需现场治理。不得在未经确认时退役调用方。
- 保持既有权限、持久化 Token 撤销、审核及日志边界。OCR、日志新采集、分区切换、GIN 与网关配置继续遵守原审批和现场门禁，不自动开启。

## 数据库与安全恢复

- 最低兼容迁移：20260715113552；最高兼容迁移：20261123170000；配置结构版本：1。以本候选实际 release-baseline.json 为准。
- 不修改历史迁移，不执行生产医疗数据修复。先授权、备份、核验归档、隔离空库恢复和版本身份检查，再按院内批准范围部署。
- 禁止直接回退到旧应用（尤其缺少持久化撤销的版本）。保留撤销、审计、正式分类与后续人工修改；优先维护/只读降级、安全前向修复，分区回退仅按独立审批的既有流程。
- 现场执行医院 A1–F4/E5 矩阵；实际 Windows Server/Nginx/NAS/OSS、Chrome86、等量副本、调用方迁移、容量/性能/RPO/RTO 和签字验收仍未取得。
