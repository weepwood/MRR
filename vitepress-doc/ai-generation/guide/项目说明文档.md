## 1. 项目概述

MRR 是一套面向病案影像管理场景的前后端一体化系统，主要用于病案/影像查询、图片浏览、统计分析、系统日志、后台管理和权限控制。

当前仓库采用多仓库结构组织：

- `frontend-repo`：Vue 3 前端应用与 VitePress 文档站
- `backend-repo`：Spring Boot 后端服务
- `mrr-db`：数据库结构参考脚本
- `docker-compose.yml`：本地联调与部署编排参考

## 2. 项目目标

当前项目重点解决以下问题：

1. 支持登录认证和基于角色/权限的后台访问控制。
2. 支持病案、统计、日志和系统信息的统一管理。
3. 支持影像浏览、打印和测试能力，方便日常联调与验收。
4. 提供可维护的数据库初始化脚本和文档中心，降低交接成本。

## 6. 登录与权限流程

### 6.1 登录流程

1. 用户在登录页输入用户名和密码。
2. 前端请求后端登录接口。
3. 后端校验数据库中的密码密文并签发 JWT。
4. 前端保存会话信息，并在路由跳转时带上权限信息。

### 6.2 路由控制

前端对后台路由做了访问控制：

- 未登录用户不能访问后台页。
- 普通用户不能进入管理员页面。
- 需要特定权限的页面会继续校验权限字符串。

### 6.3 默认测试账号

当前可用于联调的默认账号为：

- 用户名：`br_admin`
- 密码：`br_password`

该账号会由数据库初始化脚本自动写入或覆盖。若需要单独重置，可以执行：

- `backend-repo/src/main/resources/reset-br-admin-password.sql`

## 7. 数据库说明

### 7.1 主 schema

PostgreSQL 运行时使用 `app` schema，初始化脚本会自动创建以下表：

- `app.mr_auth_role`
- `app.mr_auth_user`
- `app.mr_scan`
- `app.mr_statistics`
- `app.mr_patient`
- `app.mr_user`
- `app.access_log`

### 7.2 初始化方式

后端启动时会自动执行：

- `backend-repo/src/main/resources/schema-postgresql.sql`

该脚本负责：

- 创建 schema 和表结构
- 建立常用索引
- 写入默认角色
- 写入默认用户
- 为 `br_admin` 提供可重复执行的 upsert 初始化

### 7.3 兼容说明

`mrr-db/schema.sql` 保留为历史兼容/参考脚本，不作为当前 PostgreSQL 主线启动入口。

## 8. 本地运行

### 8.1 后端

#### 环境要求

- JDK 21 或更高版本
- Maven 3.9+
- PostgreSQL 15+

#### 启动前配置

`backend-repo/src/main/resources/application.properties` 中的关键环境变量如下：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | `18045` | 后端端口 |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/imgapi?currentSchema=app` | 数据库连接 |
| `SPRING_DATASOURCE_USERNAME` | `postgres` | 数据库用户名 |
| `SPRING_DATASOURCE_PASSWORD` | `weepwood` | 数据库密码 |
| `IMAGE_URL` | `http://localhost:8005/ba-img` | 影像服务地址 |
| `IMAGE_BASE_PATH` | `./data/img` | 本地影像目录 |
| `IMAGE_USERNAME` | `br_admin` | 影像服务账号 |
| `IMAGE_PASSWORD` | `br_password` | 影像服务密码 |
| `AES_SECRET_KEY` | `change-this-in-production-32-bytes` | AES 密钥 |


## 10. 常见问题

### 10.1 后端启动报 JDK 版本不匹配

当前后端使用 Spring Boot 4 和 Java 21 级别的编译目标，不能再使用 JDK 8。请切换到 JDK 21 或更高版本后重新编译。

### 10.2 登录失败或表结构不一致

优先检查 PostgreSQL 是否已经执行过 `schema-postgresql.sql`，并确认连接串使用了 `currentSchema=app`。

### 10.3 `br_admin` 密码不生效

请执行 `reset-br-admin-password.sql`，或重新初始化数据库种子。

### 10.4 文档站打不开

请先执行一次 `npm run docs:build`，再启动 `npm run docs:dev` 或 `npm run dev`。
