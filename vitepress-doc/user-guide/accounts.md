# 账号、注册与登录

MRR 支持两种账号创建方式：用户自助提交注册申请，或管理员直接创建账号。两种方式的密码和首次使用流程不同。

## 自助注册

在登录页选择“注册账号”，填写：

- 用户名：3～40 位，只允许字母、数字、点、下划线和连字符；
- 显示名称；
- 密码：6～64 位；
- 联系方式和申请说明（按页面要求填写）。

提交成功后，账号状态为 `pending`，不能立即登录。系统会把申请默认归入待审核角色，最终角色由管理员审核时决定。

### 注册状态

| 状态 | 含义 | 是否可登录 |
| --- | --- | --- |
| `pending` | 等待管理员审核 | 否 |
| `active` | 审核通过或管理员创建并启用 | 是 |
| `rejected` | 注册申请被拒绝 | 否 |
| `disabled` | 管理员停用账号 | 否 |

审核被拒绝时，管理员必须填写拒绝原因。用户需要根据实际部署流程联系管理员处理，不要反复提交相同用户名。

## 管理员审核注册

进入“系统 → 用户管理”，筛选待审核用户。管理员可以：

1. 查看用户名、显示名称、联系方式、申请说明和申请时间；
2. 选择最终角色并批准；
3. 填写拒绝原因并拒绝；
4. 审核后查看审核人和审核时间。

审核状态可能被其他管理员同时修改。页面提示状态已变化时，应刷新列表后重新判断，不要重复提交操作。

## 管理员直接创建账号

管理员可直接创建启用账号。系统生成一次性临时密码：

- 临时密码只显示一次；
- 默认有效期由创建页面决定；
- 用户第一次登录后必须修改密码；
- 完成改密前不能访问普通业务接口；
- 改密后旧 Token 立即失效，需要重新登录。

管理员应通过受控渠道交付临时密码，不要把明文密码写入工单、聊天记录、日志或截图。

## 密码规则

当前普通密码长度为 **6～64 位**。临时密码由系统生成，避免使用容易混淆的字符。

建议：

- 使用不少于 12 位的长口令；
- 不要复用医院其他系统密码；
- 不要使用姓名、工号、科室、生日或连续数字；
- 管理员重置密码后立即完成首次改密。

## 登录限制

- 用户名或密码错误统一提示，不暴露账号是否存在；
- 登录失败过多会触发限流，通常需要等待 15 分钟；
- `pending`、`rejected`、`disabled` 状态不能登录；
- 临时密码过期后需要管理员重新生成；
- 密码修改、密码重置和首次改密会使旧 Token 失效。

## 修改密码

普通用户通过个人入口修改密码。修改成功后当前登录状态失效，需要使用新密码重新登录。

管理员不能通过“重置他人密码”接口重置自己的密码，应使用个人修改密码功能。

## 管理员重置密码

管理员重置其他用户密码时需要再次验证自己的当前密码。重置成功后：

- 目标用户现有 Token 失效；
- 系统生成新的临时密码；
- 目标用户下次登录必须改密；
- 只有启用状态账号可以重置；
- 最后一个有效管理员不能被禁用或降级。

## 注册失败排查

### 提示“请先登录”

注册接口应允许匿名访问。出现该提示通常表示部署仍在运行旧版本、前端和后端版本不一致，或 Nginx 代理到了错误后端。检查：

1. 页面显示版本与后端 `/actuator/info` 是否一致；
2. `/api/v1/auth/register` 是否被代理到当前后端；
3. 浏览器是否仍缓存旧前端文件；
4. Nginx 配置是否存在重复或错误的 `/api/` 转发规则。

### 提示用户名已存在

用户名在所有账号状态中都必须唯一。被拒绝或停用的旧账号仍会占用用户名，需要管理员处理原账号。

### 审核通过后仍无法登录

检查账号是否为 `active`、密码是否正确、是否触发登录限流，以及前端请求是否进入当前后端实例。
