# 数据关系工作台

当“病案能查到但图片缺失”“患者、统计和装箱信息对不上”时，使用数据关系工作台。它将不同来源的记录放在一起，帮助判断异常发生在哪里，而不是让用户直接改数据库。

**入口：** 数据治理 → 数据关系工作台。只查看一份病案的相关信息时，也可从业务中的“病案工作台”进入对应视图。

## 1. 先理解这些记录如何关联

<p class="doc-figure"><a :href="figure1" target="_blank" rel="noopener noreferrer" aria-label="病案资料关系图（在新标签页查看原图）"><img :src="figure1" alt="病案资料关系图" loading="lazy"></a></p>

*图 1 · 一份病案可能关联多张扫描页、统计及装箱记录；患者的遗留匹配不等同外键。*

系统用病案主档作为相对稳定的关联中心，其内部编号叫 `archive_id`。统计、扫描和装箱记录使用它建立关联；患者资料仍按 BAH 作兼容匹配，不能仅因姓名或病案号相似就认定是同一人。用户无需记住表名即可完成查询。

## 2. 查看总览并找到问题

总览提供主档数量、关联覆盖情况、最近一次质量检查与异常摘要。大规模扫描表的部分统计来自 PostgreSQL 估算，不能理解为每条记录均已实时检查。

1. 先查看检查批次和时间，确认是否为当前需要的范围。
2. 按病案号、上架号或内部主档 ID 查询。
3. 打开病案对比，查看统计、患者、装箱、扫描样本和迁移汇总。
4. 对照来源字段，判断是否缺失、冲突或仅格式不同。

| 比对状态 | 用简单的话解释 |
| --- | --- |
| 完全一致 EXACT | 当前比较字段的值相同 |
| 仅格式差异 FORMAT_ONLY | 例如 123 与 00000123，值在比较规则下相同，但原始编号仍不同 |
| 冲突 CONFLICT | 两边实际值不同，需要人工核实 |
| 缺失 MISSING | 来源记录缺少该字段 |
| 主档缺失 NO_CANONICAL | 主档没有对应值，不宜用主档覆盖来源 |

::: tip 仅格式差异不是自动修复许可
比较时可忽略纯数字编号的前导零，但保存、查询和文件路径仍保留原值。不能据此批量删除前导零。
:::

## 3. 运行检查与核对样本

候选默认关闭自动定时质量检查；管理员可按需发起手动检查。检查批次可读取状态，是否支持取消以运行模式与权限为准。扫描相关检查有近期范围和样本上限，关联覆盖估算与抽样异常都不等于全量精确计数。

常见检查包括编号或页码缺失、关联缺失与错连、编号冲突、重复扫描页、迁移状态与对象记录不一致。先确认具体异常样本，必要时重新检查，不以旧批次直接决定当前数据的处理。

## 4. 根据证据选择处理方法

<p class="doc-figure"><a :href="figure2" target="_blank" rel="noopener noreferrer" aria-label="数据治理与证据核对（在新标签页查看原图）"><img :src="figure2" alt="数据治理与证据核对" loading="lazy"></a></p>

*图 2 · 先检查证据，再区分只读预览、人工记录与真正写入。*

三种操作必须区分：

| 操作 | 是否改变病案数据 | 适用场景 |
| --- | --- | --- |
| 修复预览 | 否 | 查看候选主档、唯一性及建议动作 |
| 异常人工决策 | 否；记录决策历史 | 确认样本、暂缓处理、重新打开 |
| 关联修复工单 | 执行阶段可能改变关联 | 仅针对唯一确定、允许修复的关联 |

人工确认样本不会关闭整个案件，不会隐藏原质量检查异常。逐记录只读复验用于观察当前状态，不代表已自动修复。读取失败时不要把空白解释成无记录。

### 关联修复工单如何使用

当前候选已实现受控工单机制，工单和人工决策写入共用的开关默认关闭。只有部署启用该能力、具备必要权限且存在确定性候选时，才可能出现提交入口。

- 提交工单后由不同于提交人的授权人员审批。
- 审批后按页面允许的操作执行，服务端重新核对实际关联。
- 执行完成后进行复验，查看历史与处理前后证据。
- 取消、条件补偿和异常重开不是任意撤销或全量回滚，必须符合当前状态及服务端条件。

候选不唯一、来源不明、记录已经变化或权限拒绝时停止操作。不要通过手工 SQL 替代工作台。

## 5. 权限与故障恢复

| 功能 | 当前候选的权限边界 |
| --- | --- |
| 打开工作台、读取摘要 | system:read |
| 读取异常样本、详情和预览 | system:read + record:read |
| 提交或取消质量检查 | system:manage |
| 关联修复工单、人工决策 | system:manage + record:manage；操作还受开关、身份和状态约束 |

如果历史、详情或复验读取失败，先刷新当前案件。明确拒绝访问时停止操作并核对账号权限；写入结果未知时先确认实际状态再决定是否重试。
