# 常见问题

## 登录与页面

### 登录后看不到某个菜单

菜单由角色权限控制。先确认账号是否拥有对应权限；直接输入路由也会经过权限校验，不能通过隐藏菜单绕过。

### 页面切换后数据重新加载

影像档案袋属于沉浸式页面，不长期缓存页面实例。离开后再次进入会根据 URL、系统设置和本地状态恢复必要信息，并重新请求数据。

### 浏览器提示版本过低

最低支持 Edge 111、Chrome 111、Firefox 114、Safari 16.4。不支持 Internet Explorer、Edge IE 模式和旧版 EdgeHTML。建议使用医院统一维护的最新版 Edge 或 Chrome。

## 病案号与上架号

### 是否需要把编号补齐到 8 位？

不需要。系统数据库和本地图片路径保留原始格式。`123` 与 `00000123` 是两个不同的原始字符串，不应为了显示整齐自动改写。

### 为什么高位病案号要求上架号？

病案号从 `10000000` 开始可能重复，单独使用病案号不能保证定位到唯一档案，因此必须同时提供上架号。

### 已经被补零的数据如何修复？

系统无法可靠判断哪些前导零来自原始数据、哪些来自历史自动补零，因此不会自动删除。应根据原始数据源或可靠映射重新导入或修复，并同步核对图片文件夹。

## 影像档案袋

### 图片为空或打不开

按顺序检查：

1. 病案号和上架号是否与原始数据一致。
2. 高位病案号是否同时提供上架号。
3. 系统设置中的图片来源是本地还是 OSS。
4. 本地图片目录、文件名和服务地址是否正确。
5. OSS 记录是否已迁移、签名是否有效。
6. 浏览器网络面板中的 HTTP 状态和后端日志。

### 最近查询记录保存在哪里？

最近查询保存在当前浏览器的 `localStorage`，最多保留 20 条。记录不包含身份证号、患者姓名或后端访问令牌；清理浏览器站点数据后会消失。

### OSS 模式下为什么仍返回本地图片？

只有存在有效 `oss_url` 的图片才生成 OSS 签名地址。未迁移、签名为空或签名失败时，系统会回退本地图片，保证档案仍可访问。

### 下载整袋是否从 OSS 获取？

当前服务端 ZIP 下载仍以本地存储为来源。档案袋预览和浏览器端操作使用系统设置选中的有效图片 URL。

## 打印与 PDF

### PDF 导出提示跨域

浏览器端 PDF 需要直接读取图片 Blob。图片服务必须返回允许管理端来源的 CORS 响应头。不要关闭浏览器安全策略，也不要把 `Access-Control-Allow-Origin` 随意设置为不受控的来源。

### 只选了一部分图片，导出顺序是什么？

系统按当前选择列表的顺序处理。导出前应核对页码、病案类型和选中数量。

### 一张图片失败会怎样？

图片请求、空文件或解码失败会中止本次 PDF 导出。先定位失败图片并确认其 URL 可正常访问。

## 统计与监控

### 统计分析为什么默认只看到近 90 日？

趋势图默认缩放到最近 90 日，但后端返回全部日期汇总。可以在图表区域使用鼠标滚轮放大或缩小时间范围。

### 页面数量与数据库统计不一致

先确认筛选条件、日期范围、记录数与页数单位，再从统计明细下钻到具体病案。管理员还应检查数据质量结果、`archive_id` 关联覆盖率和异常导入记录。

### `/status` 打不开是否表示系统一定停机？

状态页与主后端同一部署。后端完全停止时状态页也无法访问，因此它适合展示恢复后的历史可用性，不等同于独立外部监控探针。

## 文档

### 用户手册与内部文档有什么区别？

用户手册描述页面操作；内部文档包含架构、数据库、部署、安全和运维信息。内部文档和实时 API 文档需要管理员或 `system:read` 权限。

### 文档内容与页面不一致

先查看更新说明和 Git 更新记录，再以当前分支代码、实际 Flyway 迁移、页面权限及接口响应为准。
