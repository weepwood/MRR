# 影像档案袋

影像档案袋用于查询、浏览、选择、打印和导出病案扫描图片。它不是 DICOM 诊断工作站，不提供窗宽窗位、医学测量或诊断标注。

## 打开方式

### 病案号查询

```text
/archive?bah=123
```

病案号小于 `10000000` 时可以单独查询。编号保留数据库原始格式，不自动补零。

### 上架号查询

```text
/archive?sjh=456
```

上架号非空且唯一时可以单独查询。

### 高位病案号查询

```text
/archive?bah=10000000&sjh=456
```

病案号大于或等于 `10000000` 时可能重复，必须同时提供上架号。

### 身份证查询

```text
/archive?id=123456789123456789
```

处理流程：

1. 系统校验身份证格式；
2. 后端查询该患者关联的病案；
3. 页面展示病案列表；
4. 查询成功后，地址栏中的身份证明文替换为服务端不透明令牌；
5. 刷新或前进后退时通过令牌恢复查询。

不要在截图、日志或工单中复制完整身份证号。

### 外部系统调阅

HIS、EMR 等系统通过一次性 Ticket 打开：

```text
/archive/external?ticket=...
```

外部入口复用影像档案袋查看能力，但不展示普通搜索卡片。Ticket 包含外部用户身份、查询条件、有效期和来源限制，用于访问审计。

## 编号与目录规则

- `bah`、`sjh` 只去除首尾空格；
- `123` 保持为 `123`；
- `00000123` 保持为 `00000123`；
- 不得为了显示整齐自动补齐固定长度；
- 数据库编号、图片目录和查询参数应保持一致。

编号格式不一致时，即使记录存在也可能无法定位图片。

## 页面区域

查询成功后通常包含：

- 患者和病案摘要；
- 身份证查询场景下的关联病案列表；
- 图片类型筛选；
- 缩略图或列表导航；
- 单页或连续滚动预览；
- 当前图片序号、页码、类型和选择状态；
- 下载、打印和 PDF 导出按钮；
- 导出任务进度、取消、重新下载和错误信息。

未查询到图片时，不显示下载、打印和 PDF 操作。

## 图片类型

类型 `0` 表示“暂未分类”，正式类型为 `1`～`15`。完整名称见 [病案类型](./medical-record-types.md)。

“暂未分类”与“14-其它”不同：前者尚未确认，后者已经确认属于其它资料。

当前主分支中，图片类型修改接口仍继承 `record:read`。`record:edit` 已在权限体系中定义，但尚未应用到该接口；权限边界以后端当前实现、运维诊断中心权限矩阵和运行中的 OpenAPI 为准。

## 图片来源与降级

管理员可以在系统设置中选择本地或 OSS。后端按每一张图片解析来源，因此同一病案可以同时存在 OSS 和非 OSS 图片。

### OSS 优先

1. 存在有效 OSS 对象时，通过后端 SDK 读取或生成受控地址；
2. OSS 缺失、签名失败或对象不可用时，降级到 Nginx/NAS/HTTP/本地；
3. 未迁移图片仍可正常查看和导出。

### 非 OSS 来源

1. 根据图片路径匹配 `default`、`BA01`、`BA02`、`BA03` Nginx 节点；
2. 再尝试配置的 NAS 或 HTTP 节点；
3. 后端能直接访问时，最后尝试本地目录。

### 混合来源注意事项

- 不要假设整份病案都在同一存储中；
- 导出任务会统计实际使用的来源数量；
- 单张图片失败可能导致整个 ZIP/PDF 失败；
- 排查时应记录失败文件、解析来源和后端错误信息。

管理员可在[运维诊断中心](./operations-center.md)输入病案号、上架号或图片 ID，查看每一步解析、匹配和回退过程。

## 最近查询

最近查询仅在成功加载图片后写入当前浏览器：

- 最多保留 20 条；
- 同一病案再次查询时移动到最前；
- 支持重新查询、删除单条和清空；
- 多标签页同步；
- 不保存身份证号、患者姓名、科室或访问令牌。

## 浏览模式

系统设置可以控制：

| 设置 | 说明 |
| --- | --- |
| 影像栏模式 | 缩略图或列表 |
| 预览模式 | 单页或连续滚动 |
| 缩略图目标宽度 | 同步影响导航区域宽度 |
| 首批渲染数量 | 控制首次挂载图片数量 |
| 自动适应预览区域 | 开启时按容器缩放，关闭时允许滚动 |
| 记住选中图片 | 按病案号和上架号恢复选中项 |

## 全屏预览

单页模式下点击图片可进入全屏预览：

- 从当前图片打开；
- 使用上一张、下一张切换；
- 第一张和最后一张不循环越界；
- 全屏切换后主页面当前图片同步；
- 关闭后保留最后查看位置。

## 权限

| 操作 | 当前主分支权限 |
| --- | --- |
| 查看图片 | `record:read` |
| 修改图片类型 | `record:read`（当前接口仍继承读取权限） |
| 下载 ZIP | `record:download` |
| 导出 PDF | `record:pdf:export` |
| 全部记录操作 | `record:manage` |

`record:download` 和 `record:pdf:export` 都包含读取能力，但彼此独立。可以允许用户下载 ZIP 而禁止导出 PDF，反之亦然。`record:edit` 已定义为记录编辑权限，但当前不能假定所有写接口都已经使用该权限。

## 下载 ZIP

点击“下载文件”后，系统根据病案大小和来源决定是否创建后台任务。

### 小病案

在满足同步条件时，后端可以直接返回文件。

### 大病案或混合来源病案

系统创建后台导出任务：

1. 按钮显示排队或生成状态；
2. 页面轮询任务进度；
3. 成功后自动开始下载；
4. 生成后仍可点击按钮重新下载；
5. 可以取消尚未结束的任务；
6. 临时文件过期后必须重新生成。

整袋下载会同时携带病案号和上架号。高位病案号缺少上架号时后端拒绝请求，避免下载错误病案。

## 导出 PDF

PDF 只包含当前选中的图片。每次修改选择后再次导出，都会创建与当前选择一致的新任务，不复用上一次导出内容。

后台 PDF 生成会：

- 按当前选择顺序读取图片；
- 支持 Local、Nginx、NAS/HTTP 和 OSS 来源；
- 根据图片方向生成合适的页面；
- 失败时返回具体任务错误，而不是继续下载旧文件；
- 生成成功后支持自动下载和重新下载。

PDF 导出不再依赖浏览器直接读取全部图片，因此通常不受浏览器图片 CORS 限制；但普通图片预览仍需要图片地址可访问。

## 断点下载

浏览器和后端支持时，导出文件会优先使用可恢复下载：

- 可以选择保存位置；
- 中断后可继续写入；
- 不支持文件系统访问能力的浏览器会回退普通下载；
- 下载失败不代表生成任务失败，可以在任务仍有效时重新下载。

## 任务状态

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 已创建并等待执行，界面通常显示为排队 |
| `PROCESSING` | 正在读取图片并生成文件 |
| `SUCCESS` | 文件可下载 |
| `FAILED` | 生成失败，查看错误信息 |
| `CANCELLED` | 已取消 |
| `EXPIRED` | 临时文件已清理，需要重新生成 |

切换病案或修改选择时，页面会丢弃旧按钮状态，并尽可能取消仍在运行的旧任务，避免旧任务结果覆盖当前病案。

管理员还可以在“运维诊断中心 → 后台任务”查看生成条件、处理条数、文件大小、SHA-256、过期时间、下载次数和失败原因。

## 打印选中

打印只处理当前勾选图片。打印前检查页序、纸张方向、缩放比例和选中数量。打印能力与 PDF 后台任务相互独立。

## 访问水印

档案袋可显示包含用户标识和时间的重复斜向水印：

- 登录用户默认显示用户名和 ID；
- 外部调用可使用受控外部用户标识；
- 时间按分钟刷新；
- 普通、连续滚动和全屏预览均可显示；
- 管理员可在系统设置中关闭或调整透明度。

## 常见问题

### 查询提示上架号必填

病案号大于或等于 `10000000`，请同时输入对应上架号。

### 导出一直显示上一次文件

当前版本会在选择变化时丢弃旧任务。若仍出现旧结果，检查前后端是否均已升级到同一版本、浏览器是否缓存旧前端，以及请求是否进入当前后端实例。

### 导出任务失败

检查：

1. 失败图片路径和来源；
2. Nginx/OSS 是否可访问；
3. 临时目录空间和配额；
4. 单文件和总文件大小限制；
5. 后端导出线程池是否排队；
6. 当前账号是否有对应导出权限；
7. 运维诊断中心中的部署就绪、图片来源和后台任务结果。

### 图片可以预览但 ZIP/PDF 失败

浏览器预览和后端导出使用不同访问路径。重点检查后端是否能访问 Nginx/NAS/OSS、图片来源节点配置和后端网络权限，并使用图片来源诊断确认后端实际解析路径。

### 下载中断

在任务仍为 `SUCCESS` 且未过期时重新点击下载。支持断点模式的浏览器会尝试继续；普通下载会重新开始。

更多问题见 [常见问题](./faq.md)。
