# 影像档案袋

影像档案袋相当于一份病案的电子文件夹：查询到正确病案后，可以查看扫描页、选择需要的页，并在授权范围内打印、下载 ZIP 或导出 PDF。它不是 DICOM 诊断工作站，不提供窗宽窗位或医学测量。

**入口：** 业务 → 影像档案袋；也可从记录管理或统计明细中的病案进入。

## 1. 先找到正确病案

<p class="doc-figure"><a :href="figure1" target="_blank" rel="noopener noreferrer" aria-label="病案编号查询决策图（在新标签页查看原图）"><img :src="figure1" alt="病案编号查询决策图" loading="lazy"></a></p>

*图 1 · 根据手头已有的信息选择查询方式。示意编号，不是实际患者数据。*

| 手头有什么信息 | 如何查询 |
| --- | --- |
| 病案号小于 10000000 | 输入原始病案号，例如 `1234` |
| 病案号大于或等于 10000000 | 同时填写对应上架号，不能只填病案号 |
| 已知非空且唯一的上架号 | 可只填写上架号 |
| 身份证号 | 使用身份证查询表单，随后从关联病案列表选中正确一份 |

病案号（BAH）和上架号（SJH）不是同一个编号。前者用于病案检索，后者可帮助区分或定位实际归档记录。系统保留原值：`1234` 与 `00001234` 不应自行互相转换。

::: warning 先核对、后操作
高位病案号可能重复。即使只查到一个结果，仍应核对病案号、上架号以及页面返回的患者/病案摘要；不要凭姓名相同判断是同一人。
:::

身份证查询优先使用页面表单，查询成功后档案袋使用不透明令牌恢复相关查询。旧明文 URL 兼容入口不等于安全分享方式，历史浏览记录、代理日志仍可能残留。不要复制完整身份证号或令牌。

## 2. 认识档案袋的阅读区域

<p class="doc-figure"><a :href="figure2" target="_blank" rel="noopener noreferrer" aria-label="影像档案袋区域示意（在新标签页查看原图）"><img :src="figure2" alt="影像档案袋区域示意" loading="lazy"></a></p>

*图 2 · 功能区域示意，不是当前软件截图；标准浏览、全景平铺与窄屏的区域位置可能不同。*

- **病案摘要：** 确认当前病案、患者信息及图片数量。身份证查询时先选择关联病案。
- **图片导航：** 使用缩略图或列表选择扫描页，通过类型筛选缩小范围。
- **阅读区域：** 单页查看或连续滚动；全屏模式下可切换前后页并返回原位置。
- **操作区域：** 查看选择数量，执行全选、取消选择、打印、ZIP 或 PDF；实际显示受权限和配置限制。

查询未完成或失败时，不应从尚未核对的旧数据开始导出。

## 3. 浏览、筛选和选页

如果只需要某类资料，例如病案首页，先筛选类型，再选择真正需要的页面；导出前确认选择数量和顺序。筛选后的可见范围与已选范围不能混为一谈。

| 操作 | 如何理解 |
| --- | --- |
| 暂未分类（0） | 正式类型尚未确认 |
| 其它（14） | 已归类为其它文书 |
| 单页 / 连续滚动 | 同一病案的不同阅读方式 |
| 全景平铺 | 在网格中浏览多张影像，具体支持以部署版本为准 |
| 全屏 | 放大当前图片，关闭后核对阅读位置 |

[病案类型](./medical-record-types.md)提供完整代码说明。OCR 建议不是正式分类，只有获得授权并核对图像后才应修改正式类型。

## 4. 选择正确的输出方式

| 想得到什么 | 选择 | 操作前核对 |
| --- | --- | --- |
| 整份病案扫描文件 | 整案 ZIP | 查询完成、病案身份正确 |
| 部分扫描文件 | 选中 ZIP | 选中页数和范围 |
| 合并成一个文档 | 选中 PDF | 选中页和顺序 |
| 纸质材料 | 打印选中 | 页面方向、缩放和纸张 |

ZIP 是压缩包，保留文件；PDF 是按选中影像生成的文档，两者权限独立。选择变化后需按新的范围重新执行，不使用上次文件代替。

<p class="doc-figure"><a :href="figure3" target="_blank" rel="noopener noreferrer" aria-label="影像导出生命周期（在新标签页查看原图）"><img :src="figure3" alt="影像导出生命周期" loading="lazy"></a></p>

*图 3 · 生成完成不代表下载完成；请实际打开输出文件核对。*

系统根据实际导出计划选择直接下载、后端任务或客户端 PDF 合成。小文件不一定经过后台任务；大病案、复杂来源或较高资源消耗的导出可能进入后台处理。

## 5. 等待生成、下载并检查结果

后台任务通常显示排队、处理中或成功等状态。成功后可能自动下载，也可在文件仍有效时重新下载。

| 状态 | 你应该怎么做 |
| --- | --- |
| 排队 PENDING | 等待调度，不重复创建 |
| 处理中 PROCESSING | 查看进度，需要时取消 |
| 成功 SUCCESS | 保存文件并打开核对 |
| 失败 FAILED | 查看具体原因，处理后重新生成 |
| 已取消 CANCELLED | 核对实际终态，不使用旧任务结果 |
| 已过期 EXPIRED | 文件已不可用，需要重新生成 |

切换病案、修改选择或离开页面后，旧任务不应覆盖当前内容。当前候选会尽可能取消失效的客户端取图与旧后台任务；后台是否真正取消仍以服务端状态为准。状态读取异常不代表任务失败，先刷新核对实际状态。

支持恢复下载的浏览器及后端可以在条件满足时继续下载；普通下载失败后通常需要重新开始。文件仍有效时优先重新下载，不重复创建后台任务。完成后检查文件内容、页数和顺序。

## 6. 图片加载失败怎么办？

病案图片可能来自本地目录、Nginx、NAS、HTTP 或 OSS 对象存储。系统按照实际配置逐张解析，允许同一个病案混用来源。预览成功只说明相应访问路径可读，不能证明后端导出路径也可读。

| 现象 | 优先检查 |
| --- | --- |
| 查询不到病案 | 原始 BAH/SJH、筛选条件、查询方式 |
| 病案存在但部分图片空白 | 来源节点与文件可读性 |
| 可以预览但无法导出 | 后端来源访问、导出任务、空间与权限 |
| 下载中断 | 生成状态、文件是否过期、网络 |
| 权限拒绝 | 联系管理员核对真实授权，不尝试绕过 |

向运维人员提供错误时间、脱敏的必要编号和错误提示，使用[运维诊断中心](./operations-center.md)定位来源；不要提交真实影像、完整身份证号、密钥或签名地址。

## 7. 权限、隐私与个人浏览设置

| 操作 | 当前候选代码的接口权限 |
| --- | --- |
| 查看图片 | `record:read` |
| 修改图片类型 | 当前遗留 ImageController 接口仍继承 `record:read`；不意味着普通读者可任意改类 |
| 下载 ZIP | `record:download` |
| 导出 PDF | `record:pdf:export` |

一般扫描记录编辑另有 `record:edit`。实际操作受账号、接口和资源策略约束；权限说明不是授予权限的依据。

最近查询记录最多保留 20 条，只记录成功查询的病案定位信息，不记录完整身份证号、姓名、科室和令牌。可单条删除或清空。档案袋设置可调整缩略图/列表、单页/连续滚动、缩略图宽度、首批渲染数量、适应预览和记忆选择。水印可由管理员配置，用于提示访问身份和时间，不替代访问控制。

外部 HIS/EMR 调阅通过受控 Ticket 进入指定档案袋，使用不同的访问范围和操作界面。不要将其与普通登录后管理端混用。
