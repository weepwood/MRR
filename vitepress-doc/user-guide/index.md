# MRR 用户手册

MRR 用于管理医疗机构的患者、病案主档、扫描记录、病案图片、统计数据、实体装箱位置、访问审计、图片迁移任务和运行诊断。站点标题中的版本号由根目录 `VERSION` 在构建时自动读取，具体功能以当前部署版本、账号权限和后端接口为准。

> 页面、菜单和可执行操作会随账号权限、系统设置及部署方式变化。菜单不可见通常表示权限不足或管理员在系统设置中隐藏了该菜单。

## 推荐业务流程

1. 在“患者管理”“记录管理”或“统计明细”中确认目标病案。
2. 核对病案号与上架号的原始值，不要手工补零。
3. 进入“影像档案袋”，确认患者、病案号、上架号和图片数量。
4. 按病案类型筛选并选择需要打印、下载或导出的图片。
5. 大病案导出时观察按钮中的后台任务进度；生成完成后下载文件。
6. 管理员先在“运维诊断中心”判断运行模式和失败检查，再结合日志、运行错误、接口响应分析和系统监控定位异常。

## 重要业务规则

### 编号保留原始格式

- `bah`、`sjh` 只去除首尾空格；
- `123` 保持为 `123`；
- `00000123` 保持为 `00000123`；
- 病案号达到 `10000000` 时必须同时提供上架号；
- 非空且唯一的上架号可以单独查询。

自动补零可能导致数据库编号与图片文件夹名称不一致，从而出现图片无法访问。

### 单个病案允许混合图片来源

同一病案中可以同时存在已迁移到 OSS 的图片和仍位于 Nginx/NAS/本地目录的图片。后端会按配置逐张解析和降级，不要求整份病案一次性完成迁移。

### ZIP 与 PDF 是独立权限

- 查看图片：`record:read`；
- 修改图片类型：当前主分支接口仍继承 `record:read`；
- 下载 ZIP：`record:download`；
- 导出 PDF：`record:pdf:export`；
- `record:manage` 包含记录类上级权限。

`record:edit` 已在权限体系中定义，但不能仅根据权限名称假定所有写接口都已经使用该权限。按钮不可见或接口返回 403 时，应检查当前后端实际权限策略，不要通过隐藏前端校验绕过后端限制。

### 大病案后台导出

ZIP/PDF 可能转为后台任务：

- 按钮显示排队、生成、成功、失败或取消状态；
- 页面会轮询进度；
- 成功后自动开始下载，也可以再次点击下载；
- 支持取消未完成任务；
- 临时文件达到保留期后会变为过期，需要重新生成；
- 下载器支持断点续传时会优先使用可恢复模式。

### 身份证查询

首次可通过 `/archive?id=<身份证号>` 查询。成功后地址栏中的明文会替换为服务端不透明令牌，页面只显示脱敏信息。不要在截图、日志和工单中复制完整身份证号。

### 只读降级

数据库、Flyway、临时目录或首选图片来源等关键检查失败时，系统可能自动进入只读降级。查询和诊断尽量保持可用，业务写入、导入、迁移和新任务创建会被拒绝。管理员应先在[运维诊断中心](./operations-center.md)修复失败项并重新体检，不能通过前端或开发者模式强制绕过。

## 文档入口与权限

从“帮助 → 帮助与文档”打开：

- **用户手册**：已登录账号；
- **内部文档**：管理员或 `system:read`；
- **实时 API 文档**：管理员或 `system:read`。

系统会签发短期 HttpOnly 文档访问 Cookie。退出登录后文档访问会话被清除。

## 文档与系统不一致时

优先按照以下顺序判断：

1. 当前部署版本、页面和接口响应；
2. 当前账号权限；
3. 系统设置中的菜单、图片来源和安全配置；
4. 本手册；
5. 历史截图或旧版本说明。

遇到功能与文档明显不一致时，记录版本号、页面路由、账号角色、发生时间、Request ID 和复现步骤后提交问题。
