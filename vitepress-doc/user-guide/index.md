# MRR 用户指南

MRR 用于管理医疗机构的病案扫描记录、患者关联信息、病案图片、统计数据、实体装箱位置和访问审计。系统面向病案文件管理，不是 DICOM 诊断阅片工作站。

> 本手册对应 `main` 当前主分支。页面、菜单和可执行操作会随账号权限、系统设置及实际部署方式变化。

## 推荐使用流程

1. 在“患者管理”“记录管理”或“统计明细”中确认目标病案。
2. 核对病案号与上架号的原始值，不要为了显示整齐手工补零。
3. 进入“影像档案袋”，确认患者、病案号、上架号和图片数量。
4. 按病案类型筛选图片，选择需要打印或导出的页面。
5. 在统计页面核对记录数、页数和时间范围。
6. 管理员通过日志、访问审计、系统监控和服务状态定位异常。

## 重要业务规则

### 病案号与上架号保留原始格式

数据库和图片目录定位会保留病案号 `bah`、上架号 `sjh` 的原始格式：

- 只去除首尾空格，空白值转换为空。
- `123` 保持为 `123`，不会自动改为 `00000123`。
- 原本带前导零的 `00000123` 仍保持不变。
- 导入数据、图片文件夹和查询参数应使用同一原始值。

自动补零可能导致数据库编号与本地图片文件夹名称不一致，从而出现图片无法访问。

### 高位病案号必须结合上架号

病案号从 `10000000` 开始可能重复。查询高位病案号时必须同时提供上架号；上架号非空且唯一时可以单独查询。

### 身份证查询

可以通过 `/archive?id=<身份证号>` 首次查询。查询成功后，地址栏中的身份证明文会替换为服务端生成的不透明令牌，页面只显示脱敏信息。

### 图片来源

系统设置支持：

- **本地图片**：默认来源，按数据库记录和本地/NAS 目录读取。
- **OSS 图片**：存在有效 `oss_url` 时生成签名地址；未迁移或签名失败时回退本地图片。

服务端 ZIP 下载当前仍以本地存储为来源。

### PDF 导出

“导出 PDF”由浏览器读取所选图片并生成文件。图片服务必须允许管理端来源通过 CORS 读取图片；跨域失败应修复图片服务或 Nginx 配置，不应关闭浏览器安全策略。

## 文档入口

从“帮助 → 帮助与文档”打开：

- **用户手册**：已登录账号可访问。
- **内部文档**：管理员或拥有 `system:read` 权限的账号可访问。
- **实时 API 文档**：管理员或拥有 `system:read` 权限的账号可访问。

系统会签发短期 HttpOnly 文档访问 Cookie。退出登录后文档访问会话会被清除。

遇到文档与页面不一致时，以当前代码、页面权限和实际接口响应为准。
