# 日志、审计与监控

## 日志管理

进入“运维 → 日志管理”，需要 `log:read` 权限。

日志页面用于查询系统请求和操作记录。可用筛选项与详情字段以当前页面为准，常见内容包括：

- 请求时间
- 操作账号
- 请求方法和接口路径
- 响应状态
- 执行耗时
- 客户端或访问来源信息

排查问题时，先缩小时间范围，再结合账号、路径、状态和关键字筛选。日志中不应记录完整身份证号、密码、JWT、AES 密钥或 OSS 凭据。

## 病案图片访问审计

进入“运维 → 病案图片访问审计”，需要 `log:read` 权限。

页面使用统一 ECharts 组件展示：

- 访问趋势
- 操作类型分布
- 用户访问排行
- 审计明细

该页面用于回答“谁在什么时间访问了哪些病案图片、执行了什么操作”。发现异常访问时，应同时核对账号权限、操作日志和相关病案。

## 接口响应分析

进入“运维 → 接口响应分析”，需要 `system:read` 权限。

页面用于观察：

- 请求数量趋势
- 响应耗时趋势
- 状态或结果分布
- 异常波动

请求量和响应耗时可能使用不同坐标轴。分析时应结合时间范围、接口路径和后端日志，不能只根据单个图表点位判断故障。

## 系统监控

进入“运维 → 系统监控”，需要 `system:read` 权限。

当前页面整合应用与数据库监控信息，包括：

- PostgreSQL 可用性
- HikariCP 连接池状态
- 表空间与容量信息
- 锁等待
- 长事务
- 数据质量检查结果
- 运行指标摘要

前端不会直接访问 Actuator 指标端点。后端统一读取或聚合监控数据后，通过受权限保护的业务接口提供给前端。

### 手动数据质量检查

数据质量检查默认不自动执行：

```properties
app.data-quality.enabled=false
app.data-quality.cron=-
```

管理员可在系统监控页面点击“立即检查”。首批检查覆盖：

- 病案号或上架号缺失、格式异常
- 页数无效
- 文件元数据缺失
- 迁移记录与 OSS 状态不一致
- 迁移未校验
- 疑似重复扫描页
- 统计记录关联异常
- 档案装箱异常

检查结果包含批次、规则结果和受限制的异常样本。Prometheus 只输出低基数聚合指标，不把病案号、上架号或患者字段作为标签。

## 服务状态

公开路由 `/status` 不要求登录，展示脱敏后的服务状态：

- 当前状态
- 当前状态持续时间
- 最近 90 天可用率
- 每日状态块
- 异常时间区间

后台“服务状态”菜单会跳转到 `/status`。

状态页与主后端属于同一程序，因此后端完全停止时页面也无法访问。服务恢复后，系统根据最后心跳和超时阈值补录停机区间。

### 状态计算

可用率按实际运行区间时长计算：

```text
可用率 = (监控时长 - DOWN 时长) / 监控时长
```

不是按心跳成功次数计算。

## 原生监控端点

Actuator 默认使用独立端口：

```text
http://127.0.0.1:18046/actuator/health
http://127.0.0.1:18046/actuator/prometheus
```

该端口默认只监听本机，不应直接暴露到公网。Prometheus、Grafana、Alertmanager 和 postgres_exporter 的原生部署说明见仓库 `monitoring/README.md`。

## 排查顺序

1. 查看 `/status` 判断当前服务和最近异常区间。
2. 查看系统监控中的数据库、连接池和数据质量结果。
3. 查看接口响应分析确定异常时间范围和趋势。
4. 在日志管理中按时间、账号和路径定位请求。
5. 涉及图片时查看病案图片访问审计和图片服务日志。
6. 涉及迁移时核对 OSS 迁移状态与数据质量结果。

## 告警与结论

Grafana 或 Alertmanager 告警只是排查入口，不应直接等同于根因。确认故障时至少结合应用日志、PostgreSQL 状态、连接池指标和实际接口响应。
