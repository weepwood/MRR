# 病案类型

MRR 使用数字代码保存病案图片类型。类型代码是业务数据的一部分，导入、筛选、修改和统计时应保持一致。

## 类型表

| 代码 | 名称 | 说明 |
| ---: | --- | --- |
| `0` | 暂未分类 | 图片已入库，但尚未确认正式类型 |
| `1` | 01-病案首页 | 病案首页相关页面 |
| `2` | 02-病程录 | 病程记录相关页面 |
| `3` | 03-手术记录 | 手术记录 |
| `4` | 04-术后病程录 | 术后病程记录 |
| `5` | 05-护理记录 | 护理相关记录 |
| `6` | 06-会诊单 | 会诊相关文书 |
| `7` | 07-特殊检查 | 特殊检查资料 |
| `8` | 08-检验单 | 检验结果和检验单 |
| `9` | 09-医嘱 | 医嘱相关页面 |
| `10` | 10-体温单 | 体温单 |
| `11` | 11-新生儿 | 新生儿相关记录 |
| `12` | 12-出院记录 | 出院记录 |
| `13` | 13-大病史 | 大病史相关文书 |
| `14` | 14-其它 | 无法归入已有正式类型的资料 |
| `15` | 15-分娩记录 | 分娩相关记录 |

## 使用规则

- 类型 `0` 表示“暂未分类”，不是错误值。
- 正式类型范围为 `1`～`15`。
- “暂未分类”和“其它”含义不同：`0` 表示尚未确认，`14` 表示已经确认属于其它资料。
- 修改类型后应刷新档案袋，确认筛选结果、标题和统计同步变化。
- 批量导入时不要使用类型名称代替数字代码，除非导入脚本明确支持名称映射。

## 修改前检查

1. 确认当前图片属于正确的患者、病案号和上架号。
2. 查看图片内容和相邻页面，避免只根据文件名判断。
3. 修改后重新选择目标类型，确认图片能够被筛选出来。
4. 涉及批量修改时，先用少量病案验证，再扩大范围。

## 常见问题

### 为什么类型 0 可以保存？

系统允许图片先入库再分类。类型 `0` 用于表示尚未确认的图片，后续可由人工改为正式类型。

### 类型 11 是否有效？

有效。类型 `11` 为“11-新生儿”。

### 类型名称为什么与旧系统不同？

当前项目已统一使用本页列出的 1～15 类型名称。旧数据中的“病程记录”“大病历”等名称应映射到当前代码和名称，不应新建重复类型。
