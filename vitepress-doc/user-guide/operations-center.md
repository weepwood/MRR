# 运维诊断中心

运维诊断中心用于集中完成“发现问题、执行检查、跳转处理、重新验证、保留审计”的闭环。进入“运维 → 运维诊断中心”，需要 `system:read` 权限；页面路由为 `/operations-center`。

它不会替代日志管理、运行错误中心、系统监控、接口响应分析、OSS 文件浏览或 Nginx 文件浏览，而是把这些专用能力组织到统一入口。

## 页面组成

| 页签 | 主要用途 |
| --- | --- |
| 运维总览 | 查看运行模式、版本、运行时长、堆内存、导出任务、5xx 和待处理检查 |
| 全面体检 | 实时检查数据库、迁移、存储、备份、运行时、任务和错误 |
| 图片来源诊断 | 按病案号、上架号或图片 ID 查看图片解析与回退过程 |
| 病案数据完整性 | 查看 `archive_id`、OSS、上架号、断链和重复病案快照 |
| 后台任务 | 汇总 ZIP/PDF 导出任务的条件、进度、大小、校验值和过期状态 |
| 权限矩阵 | 查看接口、操作、所需权限和各角色实际访问结果 |
| 维护模式 | 开启或退出主动维护，并查看自动只读降级原因 |
| 操作审计 | 查看运维写操作、失败请求、Request ID 和响应结果 |

## 运维总览

总览集中显示：

- 当前有效运行模式和最近检查时间；
- 应用版本、Java 版本、启动时间和后端运行时长；
- JVM 堆内存使用率；
- 等待、处理、失败和已完成的导出任务；
- 近 24 小时服务端 5xx 数量；
- 部署就绪检查中未通过的项目；
- 最近一次运维操作；
- 日志、监控、响应分析、Nginx、OSS 和迁移管理快捷入口。

总览适合判断“系统现在是否可以继续写入”，不能替代具体故障页面中的详细信息。

## 一键全面体检

点击“一键全面体检”后，后端会执行当前部署环境的实时检查，通常包括：

1. PostgreSQL 连接；
2. Flyway 待执行或失败迁移；
3. 病案主数据和关联状态；
4. 导出临时目录权限、配额和剩余空间；
5. Nginx 图片节点；
6. OSS 连接与首选图片来源；
7. 最近备份时间；
8. JVM 运行状态和堆内存；
9. 导出任务积压与失败；
10. 近 24 小时服务端错误；
11. 主动维护模式状态。

每个未通过项目会显示严重级别、检查详情、处理建议和可用的页面入口。完成修复后应重新执行体检，确认检查结果已经恢复，而不是只根据旧结果退出维护模式。

## 图片来源诊断

“图片来源诊断”支持输入以下任意一项：

- 病案号；
- 上架号；
- 图片 ID。

病案号、上架号和图片 ID 至少填写一项。诊断结果会展示：

- 是否找到目标图片；
- 最终选中的来源；
- 是否发生回退及回退原因；
- 每一步解析、匹配、访问和降级结果；
- 受限制的诊断详情。

常见用途包括：

- 图片可以在数据库中查询，但页面无法打开；
- 同一病案部分图片来自 OSS，部分仍来自 Nginx 或本地；
- OSS 对象不存在、签名失败或路径不一致；
- `default`、`BA01`、`BA02`、`BA03` 节点匹配错误；
- 浏览器可以预览，但后端 ZIP/PDF 导出失败。

诊断页只用于定位来源，不会上传、移动、删除或重命名文件。

## 病案数据完整性

该页读取后台生成的最近一次完整性快照，避免打开页面时直接扫描数千万行大表。主要指标包括：

- `archive_id` 覆盖率；
- OSS 覆盖率；
- 缺失上架号数量；
- 断链记录数量；
- 重复病案组数量；
- 有效扫描图片数量；
- 各业务表总数、已关联、未关联和覆盖率。

“刷新”表示重新读取当前快照，不一定等同于立即重新扫描全部数据。需要生成新快照时，应使用对应的数据质量或后台任务能力，并关注执行成本。

## 后台任务与导出文件中心

后台任务页最多加载近期导出记录，并支持按状态筛选：

- `PENDING`：等待执行；
- `PROCESSING`：正在生成；
- `SUCCESS`：生成成功且文件可用；
- `FAILED`：生成失败；
- `CANCELLED`：任务已取消；
- `EXPIRED`：临时文件已清理。

列表展示创建时间、格式、生成条件、病案范围、处理条数、文件大小、SHA-256、过期时间、下载次数、失败原因和最终状态。

该页面用于判断任务是否真正生成成功。图片可以预览但导出失败时，还应检查后端到 Nginx、NAS、HTTP 或 OSS 的访问能力，以及临时目录空间。

## 权限矩阵

权限矩阵根据当前后端接口、权限策略和角色生成，展示：

- HTTP 方法和接口路径；
- 操作说明；
- 权限策略；
- 所需权限；
- 每个角色的允许或拒绝结果。

管理员可以保存带名称的权限版本快照，并与上一版本比较接口变化。建议在以下场景保存快照：

- 正式版本升级前后；
- 批量调整角色权限前后；
- 新增外部接口或管理接口后；
- 安全审计或权限回归测试前。

前端菜单隐藏不等于接口权限被撤销。最终访问结果以后端实际校验为准。

## 运行模式

### 正常读写

自动部署检查没有关键故障，且管理员未启用主动维护模式。查询、导入、修改、迁移和任务创建按权限正常执行。

### 自动只读降级

关键依赖故障可能触发自动只读降级，例如：

- 数据库不可用；
- Flyway 存在待执行或失败迁移；
- 导出临时目录不可写或空间不足；
- 当前首选图片来源不可用；
- 其他被标记为关键故障的部署检查。

自动降级时，查询、登录、病案查看和诊断能力尽量保持可用；业务写入、导入、迁移以及需要创建新任务的操作会被拒绝并返回维护类错误。

### 主动维护只读

管理员可在版本升级、数据库维护或批量数据修复前开启主动维护模式，并填写维护原因。系统会记录操作人、时间和请求结果。

退出主动维护只会清除人工维护状态。若关键依赖仍未恢复，系统会继续处于自动只读降级，页面不能强制绕过。

## 诊断报告

“导出诊断报告”会生成 JSON 文件，通常包含：

- 运维总览；
- 全面体检结果；
- 病案数据完整性摘要；
- 权限矩阵数量摘要；
- 最近运维操作；
- 操作系统、Java、应用版本和可用构建信息。

报告不应包含患者图片、完整身份证号、密码、令牌或完整密钥。导出后仍应按照医院内部安全要求保存和传递，不要上传到公开平台。

## 操作审计

操作审计展示运维中心的写操作和失败请求，包括：

- 操作时间；
- 用户名；
- 来源 IP；
- HTTP 方法和接口；
- Request ID；
- 执行耗时；
- 响应状态和错误摘要。

需要查看同一 Request ID 的完整上下文时，继续到[日志、审计与监控](./logs.md)中查询；用户提供错误编号时，先到“运行错误中心”定位对应 Request ID。

## 推荐操作顺序

发生故障或计划维护时，建议按以下顺序处理：

1. 记录当前版本、时间、影响范围和用户现象；
2. 必要时先进入主动维护模式；
3. 执行一键全面体检；
4. 根据失败项目跳转到专用页面修复；
5. 涉及图片时执行图片来源诊断；
6. 涉及数据时核对完整性快照；
7. 重新执行全面体检；
8. 确认自动关键故障已清除；
9. 退出主动维护模式；
10. 检查操作审计、日志和系统监控，确认服务恢复。

## 使用边界

- 运维诊断中心与主后端属于同一程序，后端完全停止时页面也无法打开；
- 数据库故障期间，部分诊断、审计或错误记录可能无法持久化；
- 完整性指标可能来自快照，不应误认为实时全表统计；
- 诊断通过不代表真实业务链路已全部验证，发布后仍需抽样查询、预览、导出和外部调阅；
- 不要通过关闭前端按钮、修改浏览器请求或开发者模式绕过后端只读保护。
