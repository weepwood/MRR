# 病案与记录

MRR 将患者、病案主档、扫描记录、统计明细、图片文件和实体装箱位置分开管理。页面看到的字段和操作受账号权限、数据库数据以及系统设置影响。

## 数据关系

当前系统使用 `mr_archive` 作为病案主档：

- 每份病案拥有稳定的 `archive_id`。
- `mr_statistics`、`mr_scan` 和 `mr_archive_box_record` 通过 `archive_id` 关联病案主档。
- 上架号允许为空；非空时应保持唯一。
- 病案号不是全局唯一，高位病案号需要结合上架号定位。

用户界面通常仍以病案号和上架号查询，`archive_id` 主要用于系统内部稳定关联。

## 记录管理

进入“业务 → 记录管理”。页面用于：

- 按页面提供的条件查询扫描记录。
- 查看单条记录详情。
- 修改当前权限允许编辑的字段。
- 多选记录后批量打包下载。
- 从病案号或上架号进入影像档案袋。

大表查询由后端限制返回数量。旧兼容查询不会无限制加载全部 `mr_scan` 数据；需要连续读取大量记录时应使用受支持的分页或游标接口，而不是反复使用深度分页。

## 患者管理

进入“业务 → 患者管理”。患者列表用于查询基础信息和关联病案，不等同于扫描记录列表。

当前患者信息可包含：

| 字段 | 含义 |
| --- | --- |
| `bah` | 病案号 |
| `name` | 患者姓名 |
| `idcard` | 身份证号，界面应脱敏展示 |
| `ruyuan` | 入院日期 |
| `admissiontime` | 入院时间或历史入院时间文本 |
| `department` | 住院科室 |
| `bingqu` | 病区 |
| `chuangwei` | 床位 |

`bingqu` 是当前正确字段名，不应继续使用旧拼写 `binqu`。

常见操作流程：

1. 输入患者、病案号、科室、病区或床位等查询条件。
2. 核对患者基础信息和关联病案。
3. 选择目标病案。
4. 根据病案号和上架号进入影像档案袋。

身份证属于敏感字段，日志、截图、导出文件和工单中不应记录完整号码。

### 患者数据统计与质量检查

患者管理页顶部提供患者数据概览：

- 患者数据总行数与去重病案号数量。
- 当前身份证号为空的病案数量及分页明细。
- 同一患者对应多份病案的分组。
- 指定年份按入院日期统计的每日病案趋势。
- 指定年份不同住院科室的病案数量分布。

统计口径：

- 年度病案数、每日趋势和科室分布均按非空 `bah` 去重，避免重复数据行放大统计结果。
- 日期优先使用 `ruyuan`；`ruyuan` 为空时，再尝试解析 `admissiontime` 的日期部分。
- 身份证号为空包括数据库 `NULL`、空字符串和只包含空格的值。
- 身份证号非空且相同、同时关联多个不同病案号时，标记为高可信“同一患者多病案”。
- 身份证号为空、仅姓名相同且关联多个病案号时，只标记为低可信“疑似同一患者”，必须人工核对，不能直接合并或删除。

同一患者分组接口只返回脱敏身份证号。完整身份证号仍受患者管理页面的显示与复制设置控制。

### 从前端导入患者数据

拥有 `record:edit` 权限的用户可以在患者管理页面点击“导入患者数据”。导入采用两步流程：

1. 选择 CSV、XLSX 或 XLS 文件并执行“校验文件”。
2. 只有字段、日期和文件格式全部通过后，才能执行“确认导入”。

文件限制：

- 单个文件不超过 20 MB，最多 100,000 行。
- CSV 自动识别 UTF-8、带 BOM 的 UTF-8、UTF-16LE、UTF-16BE 和 GB18030。
- 表头必须包含 `bah,name,idcard,ruyuan,admissiontime,department,bingqu,chuangwei`。
- 可额外保留 `brxh`、`id`、`keshicode`、`bingqucode`，这些历史字段不会写入患者表。
- `ruyuan` 使用 `YYYY-MM-DD`。
- `admissiontime` 使用 `YYYY-MM-DD HH:MM` 或 `YYYY-MM-DD HH:MM:SS`。
- 病案号和身份证号疑似被 Excel 转为科学计数法时，校验会拒绝导入。

去重规则：

- 文件内完全相同的患者行只保留一条。
- 与数据库现有记录完全相同的行不会再次写入。
- 同一病案号存在不同入院信息时，不会被误判为完全重复。
- 任何格式错误都会阻止本次文件写入，避免产生部分成功、部分失败的数据。

校验结果会显示文件编码、总行数、有效唯一行、重复行和错误行。身份证原值在错误明细中仍会脱敏。

### 导出患者数据

患者管理页支持按当前关键字筛选条件导出 Excel。导出文件可能包含敏感字段，应仅保存在受控目录中，不应上传到公开问题单或普通聊天工具。

## 统计明细

进入“业务 → 统计明细”。页面以卡片或列表展示统计结果对应的病案，常见信息包括：

- 患者姓名。
- 住院科室。
- 出院日期。
- 病案号。
- 上架号。
- 扫描页数。

页面会根据容器宽度调整卡片列数和分页数量。点击目标病案可进入影像档案袋。

## 编号规则

病案号和上架号按原始字符串保存和传递：

| 场景 | 是否允许 | 示例 |
| --- | --- | --- |
| 低位病案号单独查询 | 允许 | `123` |
| 高位病案号单独查询 | 不允许 | `10000000` |
| 高位病案号 + 上架号 | 允许 | `10000000` + `456` |
| 非空唯一上架号单独查询 | 允许 | `00000456` |

系统不会把 `123` 自动改成 `00000123`。原本含前导零的编号仍保留前导零。导入数据和图片文件夹必须使用可靠原始值。

## 档案装箱

进入“业务 → 档案装箱”。该模块用于管理实体档案箱、查看装箱汇总和箱内病案。

操作前核对：

- 箱号和预期箱号。
- 病案号与上架号。
- 箱内病案数量。
- 装箱状态和异常备注。
- 页面统计卡片与明细数量是否一致。

装箱记录通过 `archive_id` 与病案主档关联。病案号重复或上架号缺失时，不应仅凭病案号猜测关联关系。

## OSS 迁移管理

进入“业务 → OSS 迁移管理”。页面用于查看图片迁移任务、进度、校验状态和异常信息。

迁移完成不等于业务数据完全一致，还应检查：

- `mr_scan.archive_id` 关联覆盖率。
- OSS URL 与迁移日志。
- 文件校验状态。
- 系统监控中的数据质量结果。
- 实际图片 URL 是否可访问。

## 操作注意事项

- 删除、批量下载、装箱和迁移属于高影响操作，执行前确认筛选范围。
- 不要手工补零修改病案号或上架号。
- 不要在生产数据库中直接修改已经执行的 Flyway 迁移文件。
- 数量不一致时先检查筛选条件、分页、病案主档关联和数据质量结果。
- 批量导入前应备份数据库，并先用少量数据验证字段、编码和关联结果。
