# 更新说明

> 本页对应正式版本 **v0.7.2**。完整提交历史见 [Git 更新记录](./changelog)，数据库和回滚条件见内部文档中的发布基线。

## 0.7.2 重点变化

### 运行错误中心

- 聚合后端 WARN/ERROR，支持错误编号、Request ID、指纹、状态和最近发生记录；
- 未处理 500 异常会返回错误编号和 `X-Error-Id`；
- 错误查看与状态修改使用独立权限；
- 敏感凭据、身份证号和堆栈信息统一脱敏。

### 单体 JAR

- GitHub Release 同时提供前端内嵌的单体 JAR；
- 默认端口为 `8002`，可以通过 `SERVER_PORT` 覆盖；
- 同时提供 SHA-256 校验文件；
- Windows 离线 ZIP 仍是包含 Nginx、WinSW、文档和管理脚本的完整部署方案。

### 文档与运维

- 新增运维诊断中心完整指南；
- 补充全面体检、维护模式、图片诊断、权限矩阵和操作审计的真实组合权限；
- 完善图片预览、Nginx/OSS 回退与 ZIP/PDF 后台任务的排障关系；
- 明确版本标签、主分支能力、数据库迁移和回滚边界。

## 0.7.0 重点变化

### 运维与维护模式

- 运维诊断中心增加统一总览、一键全面体检、处理建议和快捷入口；
- 管理员可主动开启维护只读模式，维护状态不会覆盖关键依赖触发的自动降级；
- 诊断报告默认隐藏账号、客户端 IP 和原始错误文本。

### 统一发布制品

- 管理端前端默认内嵌到后端 JAR；
- Nginx 继续提供统一入口、维护模式、文档、图片与 API 代理；
- 保留外置前端回退，Windows 管理工具可以安全切换模式。

### 界面与质量

- 表格操作只在空间不足时显示水平省略号；
- 后端测试按变更范围分级，完整 PostgreSQL 验证显著提速；
- SPA 保留路径和诊断报告脱敏边界进一步收紧。

## 0.6.5 重点变化

### 核心业务数据交换中心

- 统一患者、统计、档案装箱和扫描记录的模板、校验、导入和导出；
- 支持 CSV、XLSX、XLS 与常见中文编码；
- 导入前可以先执行仅校验，错误会定位到行、字段和原始值；
- 导出采用可重新导入的字段格式，并限制单次大批量范围。

### 运维诊断中心

- 图片来源诊断展示本地、Nginx、OSS、Object Key 与回退过程；
- 病案完整性统计由后台生成快照，不在页面请求中直接扫描大表；
- 导出文件中心汇总 ZIP/PDF 条件、进度、大小、校验值、过期与下载次数；
- 权限矩阵展示角色与接口的实际访问关系，并可保存版本快照；
- 部署就绪检查覆盖数据库、Flyway、Nginx、OSS、临时目录和备份时间；
- 关键依赖故障时自动进入只读降级，避免继续写入不完整数据。

### OSS 迁移与文件浏览

- 按“上架号前 4 位 / 上架号-病案号”组织 OSS 目录；
- 从 Nginx 获取原图并上传 OSS；
- 上架号为空的病案进入等待补齐状态；
- 支持分阶段任务、失败重试、校验和进度展示；
- 提供只读 OSS 与 Nginx 文件浏览器用于排障。

### 患者管理

- 支持编辑患者信息；
- 支持 CSV、XLSX、XLS 导入和条件导出；
- 增加身份证为空、疑似同一患者、年度病案和科室分布统计；
- 导入流程处理字段、编码、格式、重复数据和错误明细。

### 权限、导出与开发者模式

- ZIP 和 PDF 使用独立权限：`record:download`、`record:pdf:export`；
- 大病案使用后台任务生成，支持取消、过期清理和断点下载；
- 下载次数和最后下载时间纳入任务记录；
- 开发者模式可按设置开放兼容 API，真实患者数据环境必须关闭；
- 图片诊断、导出中心和权限矩阵增加更严格的组合权限。

### 表格操作

- 表格操作按钮统一使用图标；
- 空间不足时将次要操作收纳到“更多”菜单；
- 患者、用户、日志、审计、OSS 迁移和档案装箱等页面保持一致。

## 使用前注意

### 前后端版本必须一致

升级后若仍出现旧行为，检查页面版本、`/actuator/info`、Nginx 静态缓存、后端 JAR 和浏览器缓存。

### 导出依赖后端网络

图片在浏览器中可以预览，不代表后端一定可以访问。ZIP/PDF 失败时重点检查后端到 Nginx、NAS、HTTP 和 OSS 的网络、凭据和路径。

### 文件浏览器是只读排障工具

OSS/Nginx 文件浏览器不替代影像档案袋，不提供上传、删除、移动和重命名，也不应向无业务需要的账号开放。

### 只读降级需要先修复依赖

进入只读模式后，应先修复数据库迁移、图片源、OSS 或临时目录问题，再由管理员重新检查；不要绕过降级继续写入。

## 已知边界

- 正式环境以 Windows Server 原生部署为主，不依赖 Docker；
- `mr_scan` 为数千万级大表，大范围修复、统计和迁移必须使用后台任务或分批执行；
- Token 撤销黑名单依赖后端进程内存，重启后仍需依赖密码版本和 Token 有效期；
- 菜单隐藏不等于撤销权限；
- 开发者模式只能用于受控联调，真实患者数据环境必须关闭；
- 尚未合并的 PR 和 Issue 不属于当前版本能力。
